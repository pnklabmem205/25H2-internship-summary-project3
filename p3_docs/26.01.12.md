## 구현 방법

### 앱 내부 로컬 인증 방식 사용

- 서버 없이 앱 내부 로컬 저장소에만 사용자 정보를 저장하는 로그인/회원가입 방식
- **SharedPreferences**
    - Flutter에서 제공하는 앱 내부 키-값 저장소
        
        
        ```jsx
        {
        "users": {
        "연호": "1234",
        "홍길동": "0000"
        },
        "current_user": "연호"
        }
        ```
        
        | 키 | 의미 |
        | --- | --- |
        | users | 회원가입된 모든 사용자 목록 |
        | current_user | 현재 로그인한 사용자 |
    - 휴대폰 안에만 저장됨

### 회원가입 동작 로직

1. 닉네임 입력 확인
2. 비밀번호가 4자리 숫자인지 검사
3. 로컬 저장소에 같은 닉네임이 있는지 확인

- 처음 가입하는 경우

```jsx
닉네임 없음
→ users에 저장
→ "회원가입 완료" 안내
→ 로그인은 직접 해야 함
```

- 이미 존재하는 닉네임 + 같은 비밀번호

```jsx
이미 가입된 사용자
→ 중복 안내
→ 로그인 유도
```

- 이미 존재하는 닉네임 + 다른 비밀번호

```jsx
닉네임 충돌
→ 중복 안내
→ 회원가입 불가 // 닉네임 = 유저의 고유 ID 역할
```

### 로그인 동작 로직

1. 입력 값 유효성 검사
    - 닉네임, 비밀번호가 비어있지 않은가
    - 비밀번호가 4자리 숫자인가
2. users 목록에서 닉네임 검색
3. 비밀번호 비교
4. 성공 시 current_user 저장
5. HomeScreen으로 이동

- 닉네임 + 비밀번호 모두 일치하는 경우


## 카운트 초기화 버튼 활성화 구현

https://drive.google.com/drive/folders/1Q64MTT85o7tsRSAV3mR58WmfQWF_J72I?hl=ko — `카운팅 초기화.mp4` 참고

https://github.com/pnkmem432/workout-counter-mobile/tree/extras/lib

### 목적

운동 카운팅을 하면서 

- 자세가 꼬여서 카운트가 이상하게 올라감
- 운동을 다시 0회부터 재시작 하고 싶음

등의 경우에 따라 **각 운동 화면에 있는 초기화 버튼을 누름으로써 카운팅을 다시 시작하기 위함**

**COUNT 는 0으로 리셋하되, READY/CALI는 다시 하지 않고 즉시 다시 카운트 가능하는 것을 목표로 함**

### 구현 방법

**`resetCountOnly()` 구현 — 카운트 관련 상태만 리셋**

- 화면에 표시되는 카운트 값 리셋
    - `count = 0`
- 카운팅 FSM(상태 머신) 리셋
    - 스쿼트/푸쉬업: `UP ↔ DOWN`
    - 크런치: `DOWN ↔ UP`
    - 버피: `STAND → DOWN → PLANK → SQUAT → STAND` 같은 단계 FSM 을 가지는데,
    
    초기화 후 이 상태가 이전 동작에 걸려있으면 다음 프레임에서 오작동이 생길 수 있어 초기화 시 FSM을 **기본 시작 상태**로 되돌림
    
    - 스쿼트/푸쉬업: `state="UP"`
    - 크런치: `_state="DOWN"`
    - 버피: `_state=STAND`
- 필터/누적값 리셋
    - 노이즈를 줄이기 위해 EMA 같은 값을 사용하는데
        - `ema = 0.8*prev + 0.2*now`
    - 이 값이 남아있으면 초기화 직후에도 과거 값이 영향을 주어서 필터/누적값 등을 null로 초기화
- hold/gate/miss 같은 버퍼성 변수 리셋
    - 다음과 같은 보조 변수에 대해서도 0으로 리셋
        - `holdCnt`: 조건을 N프레임 연속 만족해야 넘어가는 것들
        - `gateHoldCnt`: READY 판정 누적
        - `miss`: 포즈 인식 끊김 누적

**즉, 캘리 완료 상태나 ready 상태는 유지하면서 측정 기준은 그대로 두고, 카운트만 새로 시작**

### 운동 화면(PoseLiveScreen)

1. 사용자가 운동을 해서 COUNT가 올라감

### 세트 시간 계산

세트 시간은 `PoseLiveScreen`에서 `_setStartAt`으로 계산

- 화면에 들어오면 `_setStartAt = DateTime.now()` 로 시작 시각 저장
- 저장 버튼 누르면 `duration = now.difference(_setStartAt)`
- 저장 후에는 다음 세트를 위해 `_setStartAt = DateTime.now()` 로 다시 시작

**결과:**

**1세트 시간 = 세트 시작 시각 ~ 저장 버튼 누른 시각**

### 저장 후 카운트 리셋

- 세트마다 READY/CALI 다시 하면 **흐름이 끊기고 귀찮음**
- 기준값(캘리브레이션)은 유지해야 연속 세트가 편함
- 따라서 `resetCountOnly()`를 사용해서 카운팅 관련 변수만 초기화

### 저장 데이터 구조

**로컬 저장소 SharedPreferences 사용**

저장 구조(JSON): 

```jsx
logs_v1 = {
"userNickname": {
"YYYY-MM-DD": {
"squat": {
"sets": [
{ setIndex, reps, durationMs, savedAtMs },
...
]
},
"pushup": { ... },
...
}
}
}
```

- userNickname: AuthService의 current_user 값 (현재는 닉네임)
- dateKey: 오늘 날짜 YYYY-MM-DD
- exerciseName: widget.exercise.name (squat/pushup/crunch/burpee)
- sets: 저장 버튼 누를 때마다 1개씩 append 됨
- setIndex: (기존 sets 길이 + 1)
- durationMs: 세트 시간(밀리초)
- savedAtMs: 저장 눌렀던 시각(정렬/디버깅용)

1. POSECSV — 포즈 품질
- POSECSV 상세 내용
    
    **POSECSV**
    
    - **t_ms:** 스트리밍 시작 이후 경과 시간(ms)
    - **frame_idx:** 프레임 번호
    - **step:** 버피 FSM(상태 머신)에서 현재 단계
        - STAND → DOWN → PLANK → SQUAT → STAND가 1회 루프
    - **poseOk:** 이번 프레임 포즈를 신뢰 할 수 있는가
        - 1이면 계산/판정에 사용, 0이면 아직 READY/CALI 중이거나 포즈 품질 부족
    - **poseLen:** 랜드마크 개수 (33)
    - **hipDrop:** 서 있을 때 힙 높이 대비 얼마나 내려갔는가
        - 값이 클수록 더 앉은 상태
        - 0.45 이상 DOWN 후보
    - **torsoLvl:** 몸통이 수평에 가까운지 정도
        - `(어깨Y - 힙Y)의 절대값/refLen0` 같은 정규화 수치
        - 값이 작을수록 어깨와 힙 높이가 비슷 (=수평)
    - **angle:** (어깨 - 힙 - 무릎) 각도
        - 값이 170~180 정도면 몸이 쭉 펴진 편
        - 값이 작아지면 힙이 많이 접힌 자세
    - **handKeep:** 손 지지 유지 상태
        - 1이면 손/팔이 바닥지지 형태로 유지중
1. BURSTEP — 버피 동작 단계 + 핵심 수치
- BURSTEP 상세 내용
    
    **BURSTEP**
    
    - STAND
        - 시작/끝 단계
        - hipDrop이 작고, 서 있는 상태로 판정
    - DOWN
        - 앉거나 숙여서 내려간 상태
        - hipDrop이 충분히 커짐
    - PLANK
        - 손을 바닥에 짚고, 몸통이 수평에 가깝고, 각도도 조건 만족하면 진입
        - 2초동안 SQUAT(다리 접기) 탐색
    - SQUAT
        - 플랭크에서 다리를 접어 쭈그려 앉기 성공
        - 다시 서면 카운트 +1

### 최종 결과 및 결론

**본 실험에서는 카메라 위치(높이)와 조명 환경(light/dark)에 따라 MediaPipe 기반 포즈 인식 및 운동 카운팅 성능이 어떻게 달라지는지를 버피테스트 운동에 대해 분석함**

### 공통 관찰 결과

1. **Light 환경이 Dark 환경보다 항상 안정적**
    - 포즈 인식률이나 카운트 안정성 모두 light 환경에서 더 높은 추이를 보임
2. **카메라가 바닥(bottom)에 위치할 경우**
    - 초기 포즈 인식이 실패하거나 CALIB 까지 시간이 오래 걸림
    - 가까이 다가가서 포즈를 끌고 와야 인식되는 패턴이 반복됨

### 추천 환경

**카메라 높이: 65cm**

- 밝은 환경에서는 90cm 또는 65cm 모두 포즈 인식률이나 카운트 안정성이 높지만, 어두운 환경까지 고려했을 때 90cm 위 보다 65cm 위가 조금 더 안정적임
    - DOWN 자세나 PLANK 자세 등 낮은 자세가 있어 너무 높은 위치보다 중간 위치가 더 적합한게 아닐까 싶음
- bottom 의 경우 가만히 서 있을 때 포즈 인식이 안됨과 더불어 운동 동작 중 landmark 가 많이 튀는 현상이 나타남
