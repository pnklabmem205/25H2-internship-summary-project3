### 목표

웹캠 영상에서 얼굴을 실시간으로 추적하고, 얼굴 랜드마크(좌표)를 이용해 입/눈썹/입꼬리 변화량을 계산한 뒤 규칙 기반(임계값)으로 감정(neutral/happy/sad/angry/surprised)을 추정하여 화면에 표시한다.

### 동작 과정

1. 웹캠 프레임 읽기
2. FaceMesh로 얼굴 랜드마크 추출
3. 랜드마크 좌표로 표정 특징값 계산
    - 기준 스케일: 눈 사이 거리(정규화)
        - 얼굴이 카메라에서 멀어져도 영향 덜 받게 하기 위한 정규화
    - 입 벌림 정도: MAR (Mouth Aspect Ratio)
        - surprise 판단에 사용
    - 웃음 정도: 입 중심(lip_center_y)과 입꼬리(corners_y)의 y 차이로 계산
        - 입꼬리가 올라감
        - happy 판단에 사용
    - 슬픔: 입 중심(lip_center_y)과 입꼬리(corners_y)의 y 차이로 계산
        - 입꼬리가 내려감
        - sad 판단에 사용
    - 눈썹 사이 거리: 눈썹 안쪽 두 점 거리 / 눈 사이 거리
        - 찡그리면 눈썹 사이 거리 값 작아짐
        - angry 판단에 사용
4. 규칙 기반(임계값)으로 감정 라벨 결정
    - `classify_expression(features)`에서 아래 순서로 판정:
        1. `mar > 0.70` → **surprised**
        2. `smile > 0.10` → **happy**
        3. `corner_drop > 0.10` → **sad**
        4. `brow_dist < 0.83` → **angry**
        5. 나머지 → **neutral**
    - 즉, 이번 데모는 학습 모델이 아닌 정해둔 규칙으로 표정을 분류함

### 좌표 기반 + 임계값 방식의 한계

1. **고개를 돌리면(움직이면) 판정이 이상해진다.**
    - 화면상의 2D 좌표(x,y)로 거리/비율을 계산하는데, 고개를 돌리면 얼굴이 원근 왜곡으로 찌그러져 보이기 때문에 머리 각도 변화를 표정 변화로 착각할 수 있다.
2. **사람마다 얼굴 비율이 달라서 임계값이 개인차를 탄다.**
    - 어떤 사람은 기본 입 모양이 커서 mar이 원래 높을 수 있고, 어떤 사람은 눈썹 간격이 원래 좁을 수 도 있는 등의 사람마다 얼굴 비율이 다르기 때문에 고정 임계값은 오판 가능성이 높다.
3. **조명/가림에 취약**
    - 얼굴 일부가 가려지면 랜드마크가 불안정하게 튀거나 위치가 흔들린다.
4. **진짜 감정을 맞추는 것이 아니라 표정 모양만 구분 가능**
    - 표정 패턴만을 보기 때문에 실제 감정을 구분하지는 못한다.

### 목표

웹캠 영상에서 여러 명의 얼굴(최대 5명)을 실시간으로 검출, 추적하고, 얼굴 랜드마크(좌표)를 이용해 눈, 입, 미간의 변화량을 계산한 뒤 규칙 기반(임계값) 방식으로 감정(neutral/happy/sad/angry/surprised)을 추정하여 각 사람의 얼굴 박스 위에 ID + 감정 + 이모지 형태로 실시간 표시한다.

### 동작 과정

1. 웹캠 프레임 수집
2. 얼굴 검출 및 랜드마크 추출
    - MediaPipe FaceMesh를 이용해 프레임에서 얼굴을 자동으로 검출하고, 해당 얼굴에 대해 468개 랜드마크 좌표를 반환
3. 얼굴 박스 생성
    - FaceMesh는 얼굴 박스를 직접 제공하지 않기 때문에 468개 랜드마크의 최소/최대 좌표를 이용해 얼굴 영역 직접 계산
4. 사람별 ID 유지 (간단 트래킹)
5. 표정 특징값 계산 (랜드마크 기반)
    - 입 벌림 정도 - MAR
        - `MAR = 입 세로 길이 / 입 가로 길이`
        - 입이 크게 벌어질수록 값 증가
        - **surprised 판단에 사용**
    - 웃음
        - 입 중심과 입꼬리의 y좌표 차이
        - 입꼬리가 위로 올라갈수록 값 증가
        - **happy 판단에 사용**
    - 슬픔 - corner_drop
        - 입 중심과 입꼬리의 y좌표 차이
        - 입꼬리가 아래로 내려갈수록 값 증가
        - **sad 판단에 사용**
    - 눈 가늘어짐
        - 각 눈에 대해 `눈 세로 높이 / 눈 가로 폭` 계산
        - 화난 표정에서 눈이 가늘어지는 특성을 이용
        - **angry 판단 요소 중 하나**
    - 미간 수축
        - 미간 중앙 점(GLABELLA)과 양쪽 눈 안쪽 점 사이 거리
        - 미간이 조여질수록 값이 작아짐
        - **angry 판단 요소 중 하나**
    - 고개 회전
        - 양쪽 눈 랜드마크의 z값 차이를 이용한 yaw proxy
        - 고개를 많이 돌린 경우 angry 판정을 하지 않도록 제한
    1. 규칙 기반 감정 판정
        - `classify_expression()` 함수에서 감정을 판정함
            - `mar > 0.75` → **surprised**
            - `smile > 0.10` → **happy**
            - `corner_drop > 0.07` → **sad**
            - 눈 가늘어짐 + 미간 수축 → **angry**
            - 그 외 → **neutral**
        - 본 실험은 학습 기반 모델(CNN 등)을 사용하지 않고, 명시적인 규칙과 임계값을 이용한 규칙 기반 감정 추정 방식으로 구현함.
    2. 화면 출력
        - 각 얼굴 박스 위에 ID + 감정 라벨 + 이모지 를 실시간으로 표시

    ### 좌표 기반 + 규칙 방식의 한계
    
    1. **고개 회전 및 원근 왜곡 문제**
        - 3D 얼굴을 2D 화면 좌표로 계산하기 때문에 고개 회전 시 비율이 변형되어 오탐 가능성 존재
    2. **개인차 문제**
        - 눈 크기, 입 모양, 기본 미간 간격 등 개인차로 인해 고정 임계값 방식은 모든 사람에게 완벽히 맞지 않음
    3. **거리/해상도 의존성**
        - 얼굴이 매우 멀어질 경우 랜드마크 정밀도 저하
    4. **감정이 아닌 표정 모양만 판별**
        - 실제 감정 상태가 아니라 얼굴 근육 움직임 패턴만을 기준으로 판단
