## 최대 인식 가능 인원 수

**MediaPipe FaceMesh는 코드 설정으로 최대 인식 얼굴 수를 조절할 수 있으며, 공식 문서 기준 최대 20명까지 지원하지만, 인원 수가 증가할수록 실시간 성능과 안정성은 하드웨어 및 환경에 크게 의존한다.**

### 코드 관점에서의 최대 인원 수 설정 값

```jsx
max_num_faces = 5
```

- 한 프레임에서 동시에 처리할 얼굴의 최대 개수
- 직접 지정 가능
    - `max_num_faces = 1` → 1명
    - `max_num_faces = 5` → 최대 5명
    - `max_num_faces = 20` → 최대 20명 (이론적 한계)

### 문서 기준 지원 가능 최대 인원 수

여러 FaceMesh 모델 사용 문서에서는 **“FaceMesh 모델은 기본적으로 1개의 얼굴을 감지하도록 설정되어 있지만 설정 변경을 통해 최대 20명까지 감지할 수 있다.”** 라고 언급되어 있음

https://mmla.gse.harvard.edu/tools/face-mesh/

![image.png](attachment:5449eece-7a10-46af-b8cb-bbf7369fb6ed:image.png)

공식 문서에 따르면 **얼굴을 처음에만 detection 하고 이후에는 tracking으로 추적하기 때문에 얼굴이 많아질수록 detection ↔ tracking 전환이 잦아지면서 성능이 저하될 수 있다**고 언급되어 있음

- 성능 저하는 누적되는 것이 아니고 사람 수가 줄어들면 성능은 다시 회복됨
- 다수의 얼굴이 동시에 존재하는 상황에서 detection 연산이 증가함에 따라 발생하는 일시적인 처리 부담을 의미함

### 1. 목표

FaceMesh로 Head Pose가 얼마나 멀리서까지 안정적으로 인식되는지, 그리고 얼굴 상단(이마/눈) 또는 하단(코/입) 을 가렸을 때 어디까지 버티는지를 랜드마크 개수(4/6/10)별로 비교한다. 또한 조명(ON/OFF) 변화가 인식 거리에 미치는 영향도 함께 확인한다.

### 2. 실험 설계

**(1) 변수** 

- 랜드마크 개수: 4개/6개/10개
- 조명 조건: 조명 ON/OFF
- 가림 조건:
    - 가림 없음: 얼굴을 아무것도 가리지 않음
    - 하단 가림: 얼굴 하단(코~입) 가림
    - 상단 가림: 얼굴 상단(이마~눈) 가림

**(2) 측정 기준**

- 화면에 초록 박스가 뜨는 순간을 각 조건에서 해당 거리부터 인식되기 시작한 최소 거리로 기록

**(3) 측정 방법**

- 멀리서부터 카메라 앞으로 얼굴 정면을 유지하며 걸어옴
    
    
    ![image.png](attachment:99f3c5ad-c3e1-49f8-b7f5-0a19fb9b2223:image.png)
    
    - 카메라(웹캠)를 삼각대로 바닥에서부터 110cm 위에 고정

![image.png](attachment:d06ba131-4c11-4650-af16-091f3c199a5b:image.png)

- 초록 박스가 처음 뜨는 거리를 기록
- 같은 방식으로 하단 가림/상단 가림을 각각 적용해서 다시 측정
- 위 과정을 조명 ON/OFF 에서 수행
- 랜드마크 개수(4/6/10) 코드로 각각 동일하게 수행

### 4. 결론

1. **랜드마크 개수가 많을수록 가림에 더 강해지는 것은 아님**
    - 가림 조건에서 랜드마크 **10개 > 4개 > 6개** 순으로 안정적인 경향이 관찰
    - 가림에 대한 강인성은 랜드마크의 개수보다 **얼굴의 상단, 하단, 좌우를 얼마나 균형 있게 포함하고 있는지에 더 크게 의존함**
        - 6개의 구성(양쪽 눈, 양쪽 입, 코, 턱)은 하단 영역에 의존도가 높음
        - 10개 구성(6개+양쪽 볼+양쪽 눈 안쪽)은 분산된 랜드마크를 포함함
        - 4개 구성(양쪽 눈, 코, 턱)은 보다 상단 영역에 의존도가 높음
2. **상단 가림이 하단 가림보다 인식에 더 치명적임**
    - 랜드마크 개수에 상관없이 상단 가림 시 하단 가림 의 경우보다 인식 거리가 크게 줄었음
3. **조명 OFF의 경우 조명 ON의 경우보다 인식이 어려움**
    - 조명 OFF의 경우 모든 조건에서 인식 거리가 크게 감소함

### 5.1 Head Pose 추정의 핵심은 균형보다 기하적 안정성

Head Pose 추정은 단순히 얼굴을 잘 찾는 문제가 아니라 2D 이미지 상의 점들과 3D 얼굴 모델 간의 기하적 대응 관계를 계산하는 문제이다.

점의 개수 자체가 아닌 서로 떨어져 있고, 기하적으로 독립적인 기준점을 갖는 것이 중요하다.

얼굴의 상,하,좌,우를 대표하며 서로 거의 공선이 되지 않고 작은 오차에도 비교적 안정적인 pose 계산이 가능한 다음의 6개 기준점을 많이 사용한다.

→ **코, 턱, 왼쪽 눈 바깥, 오른쪽 눈 바깥, 왼쪽 입꼬리, 오른쪽 입꼬리**

### 5.2 랜드마크를 많이 쓰면 오히려 불리해지는 경우도 있음

1. **오차 누적 문제**
    - FaceMesh의 각 랜드마크는 소량의 위치 오차를 가지는데, 점이 많아질수록 이 오차가 누적되어 결과를 흔들 수 있음
2. **가림/왜곡된 점의 영향**
    - 가려진 영역의 랜드마크가 포함되면 전체 pose 계산을 망칠 수 있음
3. **3D 모델 대응 문제**
    - solvePnP는 모든 2D 점에 대해 3D 위치를 필요로 하는데, FaceMesh 468개에 대한 정확한 3D 대응좌표를 갖지 못함
    - 왜 FaceMesh 468개 랜드마크에 대해 가상 3D 좌표를 사용하는 것이 위험한가

**즉, 얼굴 인식에는 많은 점이 유리하지만, 자세 추정에는 소수의 신뢰 가능한 점이 더 중요하다.**
