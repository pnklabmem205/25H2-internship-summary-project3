## **1. 프로젝트 개요**

- **프로젝트 명: 907호 출입자 실시간 얼굴 인증 기반 스마트 출입 통제 시스템**
- **최종 목표: 907호 출입자의 얼굴을 감지·인증하고 출입 이력을 서버에 자동으로 기록하는  IoT 출입 시스템 구축**
- **기간: ~12/12 (금)**

### 세부 목표

### (1) 얼굴 영상 출력

- ESP32-S3-CAM 모듈을 사용해 카메라 영상을 PC 화면에 출력

### **(2) 얼굴 감지**

- 카메라에 사람이 나타나면 얼굴 위치를 실시간 탐지
    - 사람 얼굴 박스 표시
- 다양한 조명/각도에 대해 안정적으로 작동해야 함

### **(3) 얼굴 등록**

- 최소 5명의 사용자를 얼굴 데이터로 등록
- 필요 시 사용자를 지속적으로 추가 가능 (최대 치 계산 필요)
- 최대치 계산
    - **ESP32-S3-N16R8 보드 사용**
        - N 뒤 숫자 = 플래시 용량(MB)
        - R 뒤 숫자 = PSRAM 용량(MB)
        - Flash 16MB, PSRAM 8MB
    - 즉, 16MB 중 펌웨어, 라이브러리, 기타 데이터 등 제외하고 **1MB 만 얼굴용 DB** 칸에 사용한다 가정
    - ESP-WHO/ESP-DL 얼굴인식에서 얼굴 1개(= feature 1개)를 저장하는 데 **약 2,050바이트 ≈ 2KB** 정도 필요하다고 되어 있음
        - 얼굴 feature는 사진이 아닌 얼굴의 특징을 숫자로 압축한 데이터
    - 1MB ≈ 1,048,576바이트 / 얼굴 1개 = 2,050바이트
        - 이론적인 최대 개수: $2,050/1,048,576≈511개$
        - 파일 시스템 오버헤드, 여유공간 등을 고려해서 80%만 얼굴에 사용하자 가정
        - 얼굴에 실제로 쓸 용량: $1,048,576×0.8=838,860.8≈838,860 바이트$
        - **최대 feature 수:  $2,050/838,860≈409개$**
        - 한 사람 당 여러 장 등록 → 4장 등록 가정
            - **최대 사람 수=** $4/400=100명$

### **(4) 얼굴 인증**

- 등록된 사용자와 실시간 얼굴이 일치하는지 비교
- 등록되지 않은 사용자는 “Unknown” 처리

### **(4) 출입 기록 서버 저장**

- 업로드 내용:
    - user_id
    - name
    - 시간(timestamp)
    - 이벤트 (입실)

### **(5) 얼굴 Tracking (서보모터) — 추가 과제**

https://www.youtube.com/watch?v=f2TUxoaKIsA

- 사용자가 다가올 때 얼굴 중심에 맞추도록 카메라(서보)를 회전
- 데모 영상: OpenCV 기반 Tracking 참고

- **ESP32-S3-cam**

[esp32-s3_datasheet_en.pdf](attachment:392c73cb-290f-4d28-9c27-6eab57e0c746:esp32-s3_datasheet_en.pdf)

- 특징
    - ESP32-S3는 기존 ESP32보다 AI/영상 처리에 특화된 MCU
        - *Xtensa LX7 Dual-core CPU (최대 240MHz)*
        - *Vector instructions (SIMD) 지원*
            - 얼굴 감지/인식은 사진 → 숫자 → 수학 연산으로 처리됨
            - 일반 MCU는 이 연산들이 느리지만,
                
                ESP32-S3는 AI 계산을 빠르게 하기 위한 전용 명령어(SIMD) 를 포함하고 있음
                
            - 그래서 TinyML(TensorFlow Lite Micro) 모델을 MCU 내부에서 빠르게 돌릴 수 있음
    - 카메라 연결 전용 하드웨어(DVP 인터페이스) 내장
        - DVP(Digital Video Port)
            - 카메라 센서가 MCU에게 픽셀 데이터를 디지털 신호로 보내는 방식
        - *Parallel 8-bit Camera Interface 지원*
            - 카메라를 위한 전용 핀 + 전용 회로가 칩 내부에 내장되어 있음
            - OV2640 / OV5640
            
            같은 DVP(Camera Parallel Interface)를 사용하는 카메라들을
            
            그대로 꽂으면 바로 영상 데이터를 읽을 수 있음
            
    - 내장 Wi-Fi + AP 모드 지원
        - *802.11 b/g/n Wi-Fi Subsystem*
        - *SoftAP 모드(Access Point Mode) 지원*
            - 공유기에 연결되는 STA 모드 (ESP32가 공유기에 접속하는 모드)
            - 보드 자체가 Wi-Fi를 발사하는 AP 모드 (ESP32가 공유기 역할을 하는 모드)
            - 즉, ESP32가 작은 Wi-Fi 공유기가 될 수 있음
    - USB-C 하나로 전원/업로드/시리얼 출력 모두 가능
        - *USB 1.1 OTG 기능 내장*
        - *USB-CDC(가상 시리얼) 지원*
            - ESP32-S3는 USB 기능이 칩 안에 직접 들어있어 전원 공급, 펌웨어 업로드, Serial Monitor 출력 모두 가능

    ### **기본 스펙 비교**
    
    | 항목 | **OV2640** | **OV5640** |
    | --- | --- | --- |
    | **해상도** | 2MP (UXGA 1600×1200) | 5MP (2592×1944) |
    | **픽셀 크기** | 2.2 μm × 2.2 μm | 1.4 μm × 1.4 μm |
    | **프레임레이트** | UXGA 15fps, SVGA 30fps, CIF 60fps | 1080p 30fps 지원 |
    | **출력 포맷** | JPEG, YUV422/420, RGB565/555, Raw8/10 | JPEG, YUV, RGB, Raw10/8 |
    | **렌즈 사이즈** | 1/4" | 1/4" |
    | **S/N Ratio** | 40 dB | 약 38 dB |
    | **인터페이스** | DVP (8bit/10bit Parallel) | DVP + MIPI (2Lane) |
    | **전력 소비** | 125mW (UXGA 15fps) | 더 높음(고해상도라 전력 ↑) |
    - **해상도: 사진이 얼마나 선명한지**
        - 숫자가 클수록 더 많은 점(픽셀)로 이미지를 만들기 때문에 얼굴이 더 선명하게 보임
        - 고해상도 일수록 얼굴 디테일이 많아서 인식 정확도가 증가할 것으로 예상
        
        ![image.png](attachment:5b6f8848-2f66-4cb6-88cf-40ba0973ab11:image.png)
        
        - 영상 해상도 종류
            - 카메라가 내보내는 화면 크기(가로x세로 픽셀 수)를 말하는 등급
                - 사진/영상 크기가 종류 별로 FHD, 4K, 8K 이런 이름이 있는 거 처럼
                카메라 센서는 아래와 같이 분류
            1. UXGA(1600x1200) 
                - **U**ltra e**X**tended **G**raphics **A**rray
                - 1600 × 1200 ≈ 192만 픽셀 (약 2MP)
                - OV2640의 최고 해상도
                - fps(초당 프레임수)가 떨어짐 → **15fps**
                - 고해상도 사진 수준, 영상은 조금 끊길 수 있음
            2. SVGA(800x600)
                - **S**uper **V**ideo **G**raphics **A**rray
                - 800 × 600 = **480,000 픽셀 (0.48MP)**
                - 해상도는 낮지만 fps가 올라감 → 30fps
                - 즉, UXGA보단 흐리지만 영상은 조금 더 부드러울 수 있음
            3. CIF(352x288)
                - **C**ommon **I**ntermediate **F**ormat
                - 352 × 288 = **약 100,000 픽셀**
                - 매우 낮은 해상도
                - 대신 **fps가 매우 높음 → 60fps 가능**
                    - Tracking, 빠른 움직임 감지에 유리
                - 즉, 화질은 매우 낮지만 엄청 부드러운 영상일 수 있음
            4. 1080p(1920x1080)
                - Full HD (FHD)의 영상 규격
                - 1920 × 1080 = **약 2.07MP**
                - 고화질
                - fps는 보통 30fps
                - 유튜브 Full HD 화질과 같음
    - **픽셀 크기: 빛을 받는 작은 센서 점의 크기**
        - 픽셀이 크면 → 한 픽셀에 더 많은 빛이 들어옴 (어두운 곳에서 유리)
        - 픽셀이 작으면 → 고해상도 구현 가능 (선명한 사진 가능)
    - **프레임레이트(FPS): 1초에 몇 장의 사진을 보여줄 수 있는지**
        - 30fps = 1초에 30장 → 자연스러운 영상
        - 15fps = 약간 끊김
        - 60fps = 매우 부드러움
        - 얼굴 Tracking(서보 따라가기) 하려면 fps 중요할 수 있음
    - **출력 포맷: 카메라가 찍은 영상을 어떤 형태로 내보내는지**
        - JPEG: 우리가 아는 일반 사진 파일
        - YUV: 영상용 색 표현 방식
        - RGB565: 빨/초/파 를 숫자로 저장
        - Raw8/10: 보정 전 raw 데이터
    - **렌즈 사이즈: 카메라 렌즈 크기**
    - **S/N Ratio(Signal to Noise Ratio): 사진에 노이즈(지글지글한 점)이 얼마나 적은지**
        - 숫자가 높을수록 깨끗한 이미지
        - 낮을수록 노이즈가 많음
    - **인터페이스(DVP,MIPI): 카메라와 MCU가 어떻게 대화하느냐(데이터 전송 방식)의 차이**
        - DVP: ESP32 가 지원하는 일반적인 8비트 병렬 방식
        - MIPI: 더 빠른 직렬 방식(스마트폰 카메라에서 사용)

    ### **1단계: OV2640으로 초기 프로토타입 개발**
    
    이유:
    
    1. ESP32-CAM, ESP32-S3-CAM 대부분이 **기본 내장 카메라로 OV2640**을 사용
        - 관련 자료가 많음
    2. OV2640은 메모리 부담이 적어서 **초기 세팅이 훨씬 안정적이고** 빠른 테스트/디버깅 가능
        - OV2640은 **압축된 작은 JPEG 덩어리**만 ESP32에 전달
        - OV5640 같은 고성능 센서는 **압축을 덜 하고 RAW 데이터나 큰 데이터 블록**을 보냄
    3. TinyML 모델은 입력으로 **저해상도 이미지(예: 96×96, 160×160)**를 사용
        - 얼굴 감지 시 딜레이가 적기 때문에 얼굴만 잘 찾는 기능을 개발하기에는 최적

    이유:
    
    1. **해상도 2MP → 5MP로 증가**
        - 얼굴 디테일 증가 → 얼굴 인식 정확도 향상
    2. **최종 완성도 향상**
        - 등록된 사용자 수 증가 시 정확도 유지에 유리

### ① ESP-WHO (Espressif 얼굴 인식 프레임워크)

- 설명
    - Espressif가 만든 **얼굴 검출·인식 전용 프레임워크**
    - Python, PC 없이 **보드 혼자서 얼굴을 감지·인식**
- 기능
    - 얼굴 감지 (face detection)
    - 얼굴 등록 (face enrollment)
    - 얼굴 인식 (face recognition)
    
    등 얼굴 관련 기능이 많이 들어있음
    

### ② TensorFlow Lite for Microcontrollers (TFLM)

- 내용:
    - 구글에서 만든 **초경량 딥러닝 런타임**
    - 플래시/램이 적은 MCU에서 작은 모델을 돌릴 수 있음
- 활용 아이디어:
    - 복잡한 얼굴 인식은 힘듦
        - 사람 있음/없음
        - 배경/사람 구분
    1. **PC에서 TensorFlow로 소형 CNN 학습**
        - 입력: 64×64 또는 96×96 정도의 작은 이미지
    2. `.tflite`로 변환
    3. TensorFlow Lite Micro Converter로 **C 배열 형태**로 변환
    4. ESP32-S3 펌웨어에 넣고 실행
    5. TinyML 모델이 먼저 “사람 있음”이라고 판단하면
        
        그때만 OpenCV 쪽으로 영상 전송 → **최적화**
        
    - TFLM으로 ESP32-S3에 올려 **전처리용 TinyML 모델**로 사용

### ③ Edge Impulse (TinyML 툴체인)

- 내용:
    - 브라우저에서 데이터 업로드 → 학습 → 모델 최적화 → MCU용 코드 생성 해주는 플랫폼
- 활용 아이디어:
    1. ESP32-S3 카메라로 이미지 샘플 수집
    2. Edge Impulse에 업로드
    3. 분류 모델(사람/배경 등) 학습
    4. 생성된 C 코드/라이브러리를 esp-idf에 붙여넣기

### 2.2.3 진행 방식 비교

### A. PC 기반 방식

- ESP32-S3-CAM → 영상 전송
- PC(Python) → OpenCV + face_recognition + Flask 로
얼굴 감지/등록/인증 + 출입 기록 저장 처리

**장점**

- 정확도와 안정성이 높음
    - PC는 CPU, 메모리 여유가 있어 안정적
- 구현 난이도가 비교적 낮음
    - OpenCV나 face_recognition 예제가 이미 많음

**단점**

- 항상 PC가 켜져 있어야 함
- TinyML 활용성 낮음

### B. 보드 단독 방식

- TinyML/ESP-WHO 방식 활용
- ESP32-S3만으로 얼굴 감지 + 등록 + 인증 수행
- 서버에는 결과/로그만 전송

**장점**

- 출입 단말기 같은 제품 펌웨어 개발 느낌이 강함

**단점**

- 메모리 등 신경 써야할 부분이 늘어나 난이도가 높음
