# v0.6 (인증 로직)

https://github.com/pnkmem432/esp-who-face_entry/tree/v0.6/examples/human_face_recognition

## **목표**

- 누가 지나가는지 / 인증이 성공·실패했는지를 **LED 패턴으**로 한눈에 알 수 있게 만드는 것
- 핵심 포인트
    - 얼굴 검출/인식 결과를 단순 성공/실패가 아니라
        
        **IDLE → CANDIDATE → AUTHENTICATING → SUCCESS/FAIL → COOLDOWN**
        
        상태 머신으로 관리
        
    - 이 상태를 **WS2812 LED**와 **HTTP /stream 화면의 박스/라벨**에 반영

## 1. 인증 상태 흐름

### 1-1. 상태 정의

- **IDLE**
    - 조건: 얼굴 0명
    - 의미: 아무도 없음, 완전 대기 상태
    - LED: OFF
- **MULTI**
    - 조건: 얼굴 2명 이상
    - 의미: 다인원, 인증 대상 모호 → 인증 시도 안 함
    - LED: **IDLE과 동일하게 OFF**
    - 내부 상태만 따로 관리 (다인원으로 인한 미인증)
- **CANDIDATE**
    - 조건: **얼굴 1명**이 **연속 ≥ N프레임**(CANDIDATE_STREAK_FRAMES) 유지
        - 코드 상 10 프레임으로 설정
        - `static const int CANDIDATE_STREAK_FRAMES = 10;    // 10프레임 연속 단일 인원`
    - 의미: 단일 인원 + 안정적으로 잡힘 → 인증 대상 후보
    - LED: 주항
- **AUTHENTICATING**
    - 조건: CANDIDATE 직후, 실제 매칭 로직 실행 중
    - 의미: 지금 임베딩 매칭 중
    - 최소 유지 시간: **AUTHENTICATING_MIN_MS (≥ 500ms)**
        
        → 너무 빨리 SUCCESS/FAIL로 튀지 않게 시각적으로 보장
        
    - LED: 주항 빠른 깜빡임
        - ON 100ms / OFF 100ms (총 주기 200ms)
- **SUCCESS**
    - 조건: AUTHENTICATING 이후 **등록자 & 유사도 ≥ threshold**
        - threshold: 인식된 사람을 등록된 사람으로 인정할지 말지 결정하는 기준 (0~1)
            - 얼굴 임베딩 간 코사인 유사도를 계산한 값
        - `const float THRESH = 0.60f; // 인식 임계값`
    - 의미: 인증 성공 (문 열림, 또는 통과)
    - 유지 시간: **RESULT_HOLD_MS ≈ 3초** 고정 유지
    - LED: **초록 고정 ON (약 3초) → 이후 OFF + COOLDOWN**
- **FAIL**
    - 조건:
        - AUTHENTICATING 이후 매칭 실패
        - 또는 DB가 비어 있는데 얼굴이 있음(“등록 안 된 사람만 있음”)
    - 의미: 인증 실패 / 미등록자
    - 유지 시간: **RESULT_HOLD_MS ≈ 3초**
    - LED: **빨강 3회 깜빡(약 300ms ON / 300ms OFF) → OFF**
- **COOLDOWN**
    - 조건: SUCCESS or FAIL 이후
    - 의미: **1~2초 정도 재인증 금지 구간**
    - 시간: **COOLDOWN_MS**
    - 효과: SUCCESS/FAIL 직후 흔들리는 프레임에 재인증이 꼬이지 않게 함
    - LED: OFF

### 1-2. 인증 상태 Log 출력

- 실시간 인증 상태가 바뀔 때마다 CMD(log)에 상태 메시지가 출력되도록 함
    
    `LED state: <prev> -> <cur>`
    
- 그리고 MULTI (다인원) 일때에는:
    
    `MULTI_PERSON_DETECTED`
    
- 전체 상태 목록

| 상태 이름 | Log 값 | 의미 | LED 패턴 |
| --- | --- | --- | --- |
| **IDLE** | 0 | 얼굴 0명, 대기 상태 | OFF |
| **MULTI** | 1 | 얼굴 ≥2명, 인증 불가 | OFF |
| **CANDIDATE** | 2 | 단일 얼굴이 일정 시간 안정적으로 유지됨 | 주황 |
| **AUTHENTICATING** | 3 | 얼굴 1명 + 임베딩 매칭 수행 중 | 주황 빠른 깜빡임 |
| **SUCCESS** | 4 | 등록자 매칭 성공 | 초록 ON 3초 |
| **FAIL** | 5 | 매칭 실패 또는 DB 비어 있을 때 얼굴 있음 | 빨강 3회 깜빡 |
| **COOLDOWN** | 6 | 성공/실패 직후 안정화용 쿨다운 | OFF |
- 상태별 의미 상세 설명
    
    ## 0 — IDLE
    
    - 얼굴이 **0명**일 때 유지
    - SUCCESS/FAIL 후 COOLDOWN 끝나면 다시 IDLE로 복귀
    - 로그 예시: `LED state: 6 -> 0`
    
    ## 1 — MULTI
    
    - 얼굴이 **2명 이상** 감지됨
    - 인증 시도 자체를 잠시 중단 (분명한 1명이 아니므로)
    - LED는 IDLE과 동일하게 **OFF**
    - Log에 다음 메시지 추가됨: `MULTI_PERSON_DETECTED`
    
    ## 2 — CANDIDATE
    
    - 얼굴이 1명이면서 **연속 N프레임 이상 안정적으로 유지**되었을 때
    - 곧바로 인증하지 않고 약간의 안정 타임을 두어 오검출 방지
    - LED는 주황색
    
    ## 3 — AUTHENTICATING
    
    - CANDIDATE → AUTHENTICATING으로 진입
    - **임베딩 매칭 로직이 실제 수행되는 500ms 시간대**
    - LED: 주황 빠른 깜빡임 (ON 100ms / OFF 100ms)
    - 너무 빠르게 SUCCESS/FAIL로 튀지 않도록 **최소 지속시간(AUTHENTICATING_MIN_MS)** 보장
    
    ## 4 — SUCCESS
    
    - 등록자 매칭 + 유사도 threshold 통과
    - 3초 동안 초록 ON
    - 그 후 자동으로 COOLDOWN(6)으로 전이
    
    ## 5 — FAIL
    
    - 인증 중 등록자 매칭 실패 or DB가 비어 있는데 얼굴이 있음 → FAIL 처리
    - 빨강 3회 깜빡 → OFF → 자동으로 COOLDOWN
    
    ## 6 — COOLDOWN
    
    - SUCCESS/FAIL 직후 재인증을 막기 위한 1~2초 안정 구간
    - LED는 OFF
    - 끝나면 IDLE로 이동

### 2. `auth_led.hpp / auth_led.cpp`

[auth_led.hpp](https://github.com/pnkmem432/esp-who-face_entry/blob/v0.6/examples/human_face_recognition/main/auth_led.hpp)

[auth_led.cpp](https://github.com/pnkmem432/esp-who-face_entry/blob/v0.6/examples/human_face_recognition/main/auth_led.cpp)

### 역할

- **인증 상태(`AuthState`)를 실제 WS2812 LED 패턴으로 보여주는 모듈**

### 주요 요소

- **초기화**
    - `esp_err_t auth_led_init(void);`
        - `led_strip_new_rmt_device()` 로 WS2812 드라이버 생성
        - 초기 상태 LED OFF
- **LED 갱신 태스크**
    - `void auth_led_task(void *param);`
        - `while(true)` 루프
            - `AuthState cur = auth_state_get();`
            - 상태 변화 감지 → 로그 + 패턴 타이머 리셋
            - 상태별 LED 패턴 적용
            - `vTaskDelay(pdMS_TO_TICKS(50));` 로 50ms마다 갱신
- **상태별 패턴**
    - `IDLE / MULTI / COOLDOWN`
        - LED **OFF**
    - `CANDIDATE`
        - 주황 (밝기 0→100%→0, ~1초 주기)
    - `AUTHENTICATING`
        - 주황 **빠른 깜빡임** (ON 100ms / OFF 100ms)
    - `SUCCESS`
        - 초록 **고정 ON (3초)** → 이후 COOLDOWN에서 OFF
    - `FAIL`
        - 빨강 **깜빡 패턴** (설계에 따라 3초 유지 or 3번 깜빡)
- **연결 포인트**
    - 상태 정보는 직접 계산하지 않고 **오직 `auth_state_get()`만 사용**
    - 상태 전환 로직은 모두 `face_processor.cpp` 쪽에 있음
        
        → LED 모듈은 표시 전용

### 3. `face_processor.cpp`

[face_processor.cpp](https://github.com/pnkmem432/esp-who-face_entry/blob/v0.6/examples/human_face_recognition/main/face_processor.cpp)

### 역할

1. **카메라 프레임 처리**
    - YUV/RGB 포맷 → RGB888 변환
    - 얼굴 검출(`HumanFaceDetect`)
    - 얼굴 인식(`HumanFaceFeat` + cosine similarity)
    - 화면 오버레이(박스 + 이름/유사도 텍스트)
    - JPEG 인코딩(/stream 응답용)
2. **임베딩 기반 얼굴 DB 관리**
    - SPI Flash `/spiflash/faces.bin` 로 저장/로드
    - 이름-임베딩 매핑, 평균 임베딩 업데이트
    - `/faces`, 삭제 기능에 대응하는 JSON 생성/삭제
3. **인증 상태 머신 로직**
    - 프레임 단위로 얼굴 개수/인식 결과를 보고
        
        `AuthState`를 **CANDIDATE → AUTHENTICATING → SUCCESS/FAIL → COOLDOWN** 사이에서 관리
        

### 인증 상태 머신 핵심 함수

- `static void update_auth_state(size_t face_count, bool any_success);`

내부에서 사용하는 상수:

```cpp
static const int      CANDIDATE_STREAK_FRAMES = 10;    // 단일 인원 연속 10프레임
static const uint64_t AUTHENTICATING_MIN_MS   = 500;   // 최소 500ms 유지
static const uint64_t RESULT_HOLD_MS          = 3000;  // SUCCESS/FAIL 3초 유지
static const uint64_t COOLDOWN_MS             = 2000;  // COOLDOWN 2초
```

내부 상태 변수:

- `static AuthState s_logic_state;`
    
    → 현재 논리 상태 (IDLE/MULTI/CANDIDATE/…)
    
- `static uint64_t s_state_ts_ms;`
    
    → 해당 상태로 진입한 시각
    
- `static int s_single_face_streak;`
    
    → 단일 인원 연속 프레임 수
    
- `static bool s_pending_result_valid;`
    
    → AUTHENTICATING 이후 적용할 결과가 준비됐는지
    
- `static bool s_pending_result_success;`
    
    → 준비된 결과가 SUCCESS인지 FAIL인지
    

전이 규칙(요약):

- `face_count == 0`
    - `IDLE`
- `face_count >= 2`
    - `MULTI`
- `face_count == 1`
    - 연속 프레임 카운트 증가
    - `s_single_face_streak < 10` → 아직 `IDLE` 유지 (LED OFF)
    - `s_single_face_streak ≥ 10` → `CANDIDATE` → 곧바로 `AUTHENTICATING`
        - 이때 `s_pending_result_valid = true;`
        - `s_pending_result_success = any_success;`
- `AUTHENTICATING`
    - 최소 500ms 유지 후
    - `s_pending_result_success` 에 따라
        - `SUCCESS` or `FAIL` 진입
- `SUCCESS / FAIL`
    - 3초 유지 후 → `COOLDOWN`
- `COOLDOWN`
    - 2초 유지 후 → `IDLE`

**DB 비어 있을 때 예외 처리**

- `s_face_db.empty()` 인 경우:
    - 얼굴이 **없으면** → `IDLE`
    - 얼굴이 **있으면** → `FAIL` 로 표시
        
        (등록이 안 되어 있어서 누구든 항상 실패)
        

→ **등록 0명 상태에서도** 얼굴이 들어오면 빨간 FAIL LED 패턴이 나와서 등록 안 된 상태라는 걸 확인 가능
