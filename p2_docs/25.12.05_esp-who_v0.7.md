# v0.7 구현 (출입 기록 DB 연동)

[보드 git](https://github.com/pnkmem432/esp-who-face_entry/tree/v0.7/examples/human_face_recognition/main)

[서버 git](https://github.com/pnkmem432/esp-who-face_entry_server/tree/main/app)

## 1. 구현 목표

- **ESP32 쪽 얼굴 인증 로직은 그대로 유지**
    - 얼굴 감지 → 매칭 → AuthState 상태머신으로 `SUCCESS / FAIL` 확정
- **인증이 ‘성공’으로 확정되는 순간**
    - ESP32가 HTTP POST로 **출입 로그 1건**을 서버에 전송
- **서버 쪽 역할**
    - `POST /api/access-logs` : ESP32가 보내는 출입 로그를 DB에 저장
    - `GET /api/access-logs` : 최근 로그 목록을 JSON으로 반환
    - `/docs` : Swagger UI에서 GET/POST 동작을 눈으로 확인
- **관리자용 웹 UI**
    - “출입 로그” 탭에서 `GET /api/access-logs` 결과를 테이블로 표시

## 2. 서버·DB 로직 설명

### 2.1 전체 폴더 구조와 각 역할

현재 `ESP-WHO-SERVER` 기준:

```
app/
  api/
    access_logs.py      # 라우터: /api/access-logs (GET, POST) 엔드포인트
  core/
    config.py           # 설정 로직 (env에서 DB URL 읽어오기 등)
  db/
    session.py          # SQLAlchemy 엔진/세션 생성 (DB 연결)
  models/
    access_log.py       # ORM 모델: access_logs 테이블 정의
  schemas/
    access_log.py       # Pydantic 스키마: 요청/응답 데이터 형식 정의
  main.py               # FastAPI 앱 생성, 라우터 등록, DB 초기화
.env                     # DATABASE_URL 등 환경변수
```

- **models**: DB 테이블 설계도
- **schemas**: API에서 주고받는 JSON의 모양 정의
- **db/session**: DB에 연결하는 커넥션/세션 팩토리
- **api/access_logs**: 실제 API 주소(/api/access-logs)를 처리하는 함수
- **main.py**: FastAPI 서버 스타트 지점


## 4. ESP32 보드와의 연결 구조

### 4.1 보드 → 서버: 인증 성공 시 로그 전송

ESP32 로그에서 확인한 실제 요청 예:

```
AccessLog: POST http://192.168.0.20:8000/api/access-logs
body={
  "device_id":"LAB",
  "event_time":"1970-01-01T00:23:12+0000",
  "result":"SUCCESS",
  "face_id":0,
  "face_name":"yh",
  "similarity":0.7307
}
```

흐름을 정리하면:

1. `FaceProcessor`가 프레임마다 얼굴을 인식하고 매칭 수행
    - `best name=yh sim=0.765` 같은 로그 출력
2. `AuthStateMachine`이 일정 조건(연속 성공, 스코어 threshold 등)을 만족하면
    - 상태를 `AUTH_SUCCESS`로 전환 (`state -> 4` 등 로그)
3. 이 시점에 **AuthLogger** 또는 비슷한 모듈이 실행되어
    - 위 형식의 JSON을 만들어
    - `http://192.168.0.20:8000/api/access-logs` 로 HTTP POST 수행
4. 서버의 `POST /api/access-logs` 엔드포인트가 이를 받아
    - Pydantic 스키마(`AccessLogCreate`)로 검증
    - SQLAlchemy 모델(`AccessLog`)로 변환
    - DB 세션을 통해 `access_logs` 테이블에 insert 후 commit

### 4.2 보드 내장 웹 UI ↔ 서버

![image.png](attachment:927ae22a-020e-483b-9be6-be3e191f1c84:image.png)

보드 안의 `http_server_ex.cpp` 에 있는 JS 코드:

```jsx
async function fetchAccessLogs() {
  logStatus.textContent = '조회 중...';
  logTableBody.innerHTML = '';

  try {
    const res = await fetch('http://192.168.0.20:8000/api/access-logs');
    if (!res.ok) throw new Error('HTTP ' + res.status);

    const data = await res.json();  // 위에서 본 JSON 배열
    if (!Array.isArray(data) || data.length === 0) {
      logStatus.textContent = '출입 기록 없음';
      return;
    }

    data.forEach(item => {
      const tr    = document.createElement('tr');
      const tdId  = document.createElement('td');
      const tdNm  = document.createElement('td');
      const tdTm  = document.createElement('td');

      tdId.textContent = item.id ?? '';
      tdNm.textContent = item.face_name ?? '';
      tdTm.textContent = item.event_time_kr ?? item.event_time ?? '';

      tr.appendChild(tdId);
      tr.appendChild(tdNm);
      tr.appendChild(tdTm);
      logTableBody.appendChild(tr);
    });

    logStatus.textContent = '최근 ' + data.length + '건';
  } catch (e) {
    logStatus.textContent = '조회 실패: ' + e.message;
  }
}
```

UI 관점에서 보면:

- 사용자가 **“출입 로그” 탭을 클릭** → `fetchAccessLogs()` 호출
- 보드는 **자기 자신이 아니라** PC 브라우저에서
    - 서버(`192.168.0.20:8000`)로 GET 요청을 보내고,
    - 받은 JSON을 테이블로 렌더링
- 따라서 동작 조건:
    1. ESP32가 아닌 **PC 브라우저와 서버가 같은 네트워크**에 있어야 하고
    2. `CORS` 허용이 되어 있어야 함
        
        → FastAPI 쪽에서 `CORSMiddleware` 로 `*` 허용해 둔 상태

### 4.3 전체 연결 그림

- **ESP32**
    - 얼굴 인식 + 인증
    - 인증 성공 시 → 서버에 `POST /api/access-logs`
    - 웹 페이지(`/`) 제공 + JS 안에서 `GET /api/access-logs` 호출
- **FastAPI 서버**
    - `POST /api/access-logs` 로부터 로그 수신 → `access_logs` 테이블에 저장
    - `GET /api/access-logs` 로 최근 N개 반환
    - `/docs` 에 Swagger 문서 자동 생성
- **DB**
    - `access_logs` 테이블
