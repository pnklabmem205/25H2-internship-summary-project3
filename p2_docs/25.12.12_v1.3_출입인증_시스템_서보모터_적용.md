## 서보모터 위에 카메라를 올린 ESP-WHO 얼굴 트래킹 로직

## 1. 시스템 개요

카메라(ESP32-S3 CAM)를 서보모터 위에 올려 두 축(PAN/TILT)으로 회전시키고,

**얼굴이 화면 중앙에 오도록 서보모터가 카메라 방향을 조절하는 구조**

→ 즉, 카메라가 얼굴을 찾아서 그쪽을 바라보도록 회전하는 자동 PTZ 구조

---

## 2. 로직 흐름

### ① **얼굴 검출 (Detection)**

- ESP-WHO는 매 프레임 실시간 얼굴 검출을 수행
- 박스 좌표(x1, y1, x2, y2)를 통해 얼굴 중심(cx, cy)를 얻음
- `얼굴 중심 - 화면 중앙` 오차값으로 서보 회전 방향을 결정

### ② **좌표 → 각도 매핑**

- 얼굴이 화면 왼쪽이면 카메라는 왼쪽으로 회전해야 함
- 얼굴이 위에 있으면 카메라는 위로 향해야 함
- 이 오차값을 절대 각도(예: 15°, 60°, 105°)로 변환해 서보에 전달함

### ③ **서보모터 움직임**

- 일정 간격(예: 100ms)에 한 번씩만 업데이트
    
    (너무 자주 업데이트하면 진동 발생)
    
- 서보는 목표 각도에 맞춰 천천히 회전하며 얼굴 중심을 맞추려 함

---

## 3. ESP-WHO와 OpenCV의 차이 (트래킹 성능의 차이)

| 항목 | OpenCV (PC) | ESP-WHO (ESP32) |
| --- | --- | --- |
| 검출 방식 | Detection + Tracking | Detection만 있음 |
| 좌표 안정성 | 부드럽게 이어짐 | 매 프레임 튀는 경우 많음 |
| 얼굴 사라짐 처리 | Tracker가 예측 | 좌표가 아예 사라짐 |
| 모터 제어 적합성 | 매우 적합 | **제한된 안정성** |
- 핵심 차이

OpenCV는 Tracking 알고리즘(KCF, MOSSE, CSRT 등)이 있어서 **얼굴이 1~2프레임 사라져도 추정 좌표를 부드럽게 이어줌**

반면 ESP-WHO는:

- 얼굴이 흔들리면 box가 튄다
- 얼굴이 순간 사라지면 좌표가 아예 없다
- 그래서 서보 제어가 불안정해지기 쉬움

---

## 4. ESP-WHO로 서보 트래킹을 하면 발생하는 한계

### ① 얼굴 검출이 끊기면 서보가 순간적으로 멈추거나 반대로 튀는 문제

- 서보는 물리적으로 느림 (0.1~0.2초 걸림)
- 반면 ESP-WHO는 15~25fps로 표본이 빠르게 바뀜
    
    → 좌표 불연속 → **튀는 움직임**
    

### ② 박스가 흔들리는 만큼 서보도 흔들림

- Detection 기반 좌표는 픽셀 단위로 흔들림
- 모터가 계속 소각도로 흔들리거나 진동할 수 있음

### ③ 실제 PTZ 카메라처럼 부드러운 운동 예측이 없음

- Tracking이 없어서 “이전 프레임에서 이쪽 → 이번 프레임도 이쪽 방향” 같은 연속성이 없음

---

## 5. 해결 방안

### 해결 1) 히스테리시스(최근 박스 유지)

- 최근 3~8프레임 얼굴 좌표를 저장
- 얼굴 검출이 1~3프레임 끊겨도 이전 좌표를 그대로 쓴다
    
    → 갑자기 반대로 튀는 현상 방지
    

### 해결 2) 서보를 절대각도로 점프가 아니라 천천히 따라가기

- 목표 각도까지 한 번에 가지 않고
    
    → 1~2도씩 미세하게 이동
    

### 해결 3) 데드존(deadzone) 을 예민하게 설정

- 데드존: 얼굴이 약간 움직여도 서보모터가 반응하지 않도록 하는 완충 구간(정지 구간)
- 출입 단말기 앞에서 사용자는 **거의 정지 상태**에 있음
    - 얼굴이 흔들리는 범위가 작다
    - 사용자는 카메라 정면에 서 있음
    - 동작량이 적기 때문에 데드존을 키우면 **모터가 거의 안 움직이는 상황이 생김**
    
    → 즉, 데드존을 예민하게 설정하여 사람이 살짝 비껴서 서 있어도 센터에 맞춰줄 수 있도록 함
    

---

## 6. 그래도 남는 근본적인 한계

### 1) Tracking이 없으므로 완전한 “연속 좌표”를 얻을 수 없음

→ 빠르게 움직이는 얼굴을 안정적으로 따라가는 건 거의 불가능

### 2) 서보모터 자체의 물리적 한계

- 최대 속도
- 진동
- backlash(유격)
    
    → 고가 PTZ 카메라 수준의 부드러움은 불가능
    

### 3) ESP-WHO Detection 자체의 잡음

- 조명, 거리, 각도에 따라 박스가 튐

---

## 7. 결론: 현실적으로 달성 가능한 목표 수준

정확한 얼굴 추적은 어려워도 “사람 방향을 대략적으로 바라보는 PTZ 기능” 정도로 구현 가능

즉

- 기대 가능한 수준
    - 사용자가 오른쪽에 있으면 카메라가 오른쪽으로 돌음
    - 사용자가 아래쪽에 있으면 카메라가 아래쪽을 봄
    - 얼굴이 잠깐 사라져도 부드럽게 유지
- 기대하기 어려운 수준
    - OpenCV 수준의 고급 tracking
    - 아주 부드러운 카메라 이동
    - 빠른 움직임 실시간 추적
    - 스포츠 카메라·방송용 PTZ 같은 고정밀 움직임

## 3. 핵심 아이디어

### 1) 얼굴 검출 → 얼굴 중심 좌표(cx, cy) 추출

- ESP-WHO 에서 프레임마다 사람 얼굴을 검출하고 그 얼굴의 중심점 좌표(cx, cy) 를 받음

### 2) 얼굴 중심 vs 화면 중심 비교

- 화면 중심: (center_x, center_y)
- 얼굴 위치: (cx, cy)
- 오차:
    
    ```jsx
    err_x = cx - center_x
    err_y = cy - center_y
    ```
    

### 3) 오차를 정규화해 서보 회전값으로 변환

```jsx
nx = err_x / center_x   (좌우 비율)
ny = err_y / center_y   (상하 비율)
```

### 4) 데드존 적용

- 얼굴이 거의 중앙일 때는 서보가 불필요하게 흔들리는 걸 방지

```jsx
static const float SERVO_PAN_DEADZONE  = 0.02f;
static const float SERVO_TILT_DEADZONE = 0.02f;

if abs(nx) < DEADZONE → 0으로 처리
if abs(ny) < DEADZONE → 0으로 처리
```

### 5) 서보 목표 각도 생성

- 각도는 서보의 최소, 최대 범위 (SERVO_MIN/MAX) 안에 제한

```jsx
// 각도 제한 (기구적으로 안전한 범위)
static const float SERVO_PAN_MIN  = 10.0f;
static const float SERVO_PAN_MAX  = 120.0f;
static const float SERVO_TILT_MIN = 10.0f;
static const float SERVO_TILT_MAX = 120.0f;

target_pan  = CENTER_PAN  + nx * PAN_RANGE
target_tilt = CENTER_TILT + ny * TILT_RANGE
```

## 4. Tracking 한계 보안 방식

### 1) 히스토리 기반 필터링

- 최근 8 프레임의 얼굴 중심 좌표를 저장
- 8 프레임동안 흔들리는 값들을 모아 평균 값으로 계산해 부드럽게 추적

### 2) 서보 업데이트 간격 제한

- 프레임은 30fps 이면 초당 30번이 들어오는데 서보 모터를 1초에 30번 위치 이동 명령을 보낼 수 없기 때문에 서보 명령 빈도를 낮춰 흔들림을 줄이는 효과를 냄
    
    ```jsx
    static const int64_t SERVO_UPDATE_INTERVAL_MS = 100;  // 1초에 10번
    
    if now - last_update >= UPDATE_INTERVAL:
    ```
    

### 3) 이동량 제한

- 갑자기 튀는 얼굴 검출이나 얼굴 이동으로 인해 서보 모터가 확 움직이면 부드럽지 못하고 기계도 위험하기 때문에 서보가 갑자기 너무 크게 움직이지 않게 막음
    
    ```jsx
    // 한 번에 움직이는 최대 각도(부드럽게 따라가기)
    static const float SERVO_MAX_STEP_DEG = 3.0f;
    delta_pan = clamp(target - current, -MAX_STEP, +MAX_STEP)
    ```
    
    - 예) `80° → 77° → 74° → 71° → 68° → ... → 20°`
- 천천히 움직이게 함으로써
    - 자연스러운 카메라 추적
    - 서보 부하 감소
    - 진동/소음 감소

### 최종 트래킹 루프 요약

```jsx
if 얼굴 없음:
	서보 업데이트 스킵
else:
	① 최근 얼굴 좌표 히스토리 갱신
	② 히스토리로 평균 위치 계산
	③ 화면 중심과의 오차 계산
	④ 데드존 적용
	⑤ 목표 pan/tilt 각도 계산
	⑥ 업데이트 간격 체크
	⑦ 한 스텝씩 부드럽게 이동 (max step 제한)
	⑧ 현재 서보 각도 저장
```
