# v0.7 event_time 오류 해결

https://github.com/pnkmem432/esp-who-face_entry/blob/v0.7/examples/human_face_recognition/main/app_main.cpp

### 문제 정의

- 사용자의 출입 로그에서 출입 시간이 현재 한국 시간으로 찍히지 않고 1970-01-01 같은 다른 값이 찍힘

![image.png](attachment:c6b84159-ede4-4bed-a91a-b2c8a6bbb9b2:image.png)

### 문제 해결

- ESP32의 기본 시간은 ‘UNIX Epoch(1970-01-01)’ 으로 time() 을 호출하면 아무 초기화도 안 한 상태에서는 UNIX 기준 시각 (1970-01-01 00:00:00 UTC) 을 의미함
- 즉 보드의 시스템 시간이 한 번도 ‘현재 시간’으로 동기화 된 적이 없어서 항상 UNIX 기준으로 event_time 이 찍혔음
- WIFI 연결 후 SNTP + KST 타임존 설정을 통하여 동기화 함
    - 보드가 WIFI 에 연결되면 NTP 서버에서 현재 시간을 가져와서 시스템 시간을 맞추고 타임존을 한국 시간으로 설정
    - 코드
        
        
        1. 헤더 추가
        
        ```jsx
        #include "esp_sntp.h"
        #include <time.h>
        ```
        
        1. SNTP 초기화 + kST로 세팅하는 함수 추가
        
        ```jsx
        // NTP(SNTP) 초기화
        static void initialize_sntp(void)
        {
        ESP_LOGI(TAG, "Initializing SNTP");
        esp_sntp_setoperatingmode(SNTP_OPMODE_POLL);
        // 원하는 서버로 변경 가능 ([kr.pool.ntp.org](http://kr.pool.ntp.org/) 등)
        esp_sntp_setservername(0, "[pool.ntp.org](http://pool.ntp.org/)");
        esp_sntp_init();
        }
        
        // 한국 시간(KST, UTC+9)으로 맞추기
        static void obtain_time_kst(void)
        {
        initialize_sntp();
        
        time_t now = 0;
        struct tm timeinfo = {};   // 전체 0 초기화
        
        int retry = 0;
        const int retry_count = 10;
        
        // 년도가 아직 1970이면(=시간 안 맞았으면) 최대 10번 정도 기다리기
        while (timeinfo.tm_year < (2020 - 1900) && ++retry < retry_count) {
            ESP_LOGI(TAG, "Waiting for system time to be set... (%d/%d)", retry, retry_count);
            vTaskDelay(pdMS_TO_TICKS(2000));
        
            time(&now);
            localtime_r(&now, &timeinfo);
        }
        
        // 타임존을 한국(KST, UTC+9)로 설정
        setenv("TZ", "KST-9", 1);
        tzset();
        
        // 확인용 로그
        char buf[64];
        strftime(buf, sizeof(buf), "%Y-%m-%d %H:%M:%S %z", &timeinfo);
        ESP_LOGI(TAG, "Current time (KST): %s", buf);
        }
        ```
        
        1. WIFI 연결 후 main 에서 한 번 호출
        
        ```
        extern "C" void app_main(void)
        {
        ESP_ERROR_CHECK(nvs_flash_init());
        ESP_ERROR_CHECK(fatfs_flash_mount());
        
        auth_state_init();
        auth_led_init();
        xTaskCreate(auth_led_task, "auth_led_task", 2048, nullptr, 5, nullptr);
        
        // 1. Wi-Fi 연결
        wifi_init();
        
        **// 2. ★ Wi-Fi 붙은 뒤 시간 동기화 + 타임존 설정
        obtain_time_kst();**
        
        // 3. 카메라 / HTTP 서버 시작
        auto *cam = new who::cam::WhoS3Cam(
            PIXFORMAT_RGB565,
            FRAMESIZE_QVGA,
            5,
            false,
            true
        );
        ESP_LOGI(TAG, "Camera init OK");
        
        start_http_server_ex(cam);
        
        while (true) {
            vTaskDelay(pdMS_TO_TICKS(1000));
        }
        }
        
        ```

    - 정리
        - ESP-WHO 는 ESP32-S3 카메라 보드에서 얼굴 검출, 얼굴 인식 기능을 쉽게 구현할 수 있도록 만든 Espressif(ESP32 제작사)의 공식 ‘컴퓨터 비전 라이브러리 + 에제 모음’
            - 카메라 드라이버
                - 다양한 카메라 센서를 쉽게 초기화하도록 도와줌
                - 해상도 설정, 버퍼 관리, JPEG 압축, RGB 변환 등 카메라 제어 기능 포함
            - ESP-DL
                - 얼굴 인식용 뉴럴넷을 ESP32-S3용으로 최적화한 라이브러리
                - 백터 연산기 + PSRAM 활용해 빠르게 동작
                - 얼굴 임베딩 생성, 코사인거리 비교 기능 제공
            - Human Face Detect / Recognition
                - 얼굴 위치 박스를 찾아주는 모델(검출)
                    - CNN 딥러닝 모델이 카메라에서 받은 RGB 이미지가 입력되면 이미지 일부를 조금씩 훑으면서 이 부분이 얼굴일 확률, 그 얼굴을 감싸는 사각형 위치(x,y,w,h) 를 예측해 후보 박스가 여러 개 나오면 NMS 라는 과정을 통해 겹치는 박스들 중 제일 자신있는 것만 남김
                - 얼굴을 수치형 벡터로 바꿔주는 모델(임베딩)
                    - 얼굴을 숫자로 표현한 좌표값 묶음
                    - 비슷한 얼굴끼리는 임베딩 벡터끼리 가까이 모이게, 완전 다른 얼굴들은 멀리 떨어지게 되도록 학습된 신경망
                    - Detection 단계에서 나온 얼굴 영역을 받아서 네트워크 입력 크기에 맞게 리사이즈 후 정규화(0~255→0~1 or -1~1), 그 이미지를 Face Recognition CNN에 통과시켜 마지막 레이어에 나온 숫자 배열이 임베딩 백터
                - 이미 저장된 임베딩과 비교해 사람을 식별(인식)
                    - 각 사람은 고차원 공간의 한 점(좌표), 새 얼굴도 그 공간의 한 점이니 두 점 사이 거리가 가까우면 같은 사람, 멀면 다른 사람 → 코사인 유사도
            - HTTP 서버 예제
                - 웹 브라우저에서 실시간 MJPEG 스트림을 보거나 REST API 로 등록/삭제를 수행할 수 있는 구조가 이미 완성되어 있음
        - 한 사람만이 아니라 top3 후보 + 퍼센트 출력이 가능할까?
            - 현재 구조: 각 등록자와 거리 계산 → 가장 가까운 1명만 선택
            - 변경되는 구조: 거리 계산 → 정렬 → 상위 3명 선택 → 점수 계산 → 표시
        - 한 사람이 여러 번 등록한다면?
            - 기존 폴더를 그대로 둔 상태에서 같은 이름으로 새 embedding을 덮어씀
            - 임베딩들이 중복될 수 있고 얼굴 각도나 조명 달라도 저장되므로 오히려 안식률이 올라가기도 함
        - 정면 사진 한 장만 찍어도 될까?
            - 딥러닝 얼굴 인식 모델(ArcFace 계열) 은 정면 사진 1장으로 얼굴의 고유 특징을 벡터로 추출할 수 있고 약간의 각도 변화, 조명 변화, 표정 변화에 대해 강인하도록 학습됨
            - 단, 너무 옆, 역광, 마스크 착용 등의 경우는 정확도가 많이 떨어질 수 있음
            - 한 사람 당 3장 정도 찍으면 인식률 올라감 → 정면, 왼쪽, 오른쪽
                - 임베딩 3개를 모두 저장 후, 인식 시 가장 가까운 것 기준 → 여러 상태를 허용해주는 방식
                - 3개를 평균 내서 대표 임베딩 1개로 만듦
        - 임베딩 벡터가 실제로 어떤 특징을 담고 있는가?
            - 얼굴의 형태
                - 턱선 모양
                - 광대 위치
                - 눈썹 간격
                - 눈, 코, 입 크기
            - 얼굴의 질감
                - 피부톤
                - 주름 패턴
                - 눈가,입가의 특징
            - 조명/포즈 변화에 강인하도록 변환된 특징
                - 빛 방향이 바뀌어도 비슷하게 위치함
        - 임계값(threshold)은 어떻게 정하면 좋은가?
            - threshold 낮음 → 엄격 → false accept 감소
            - thershold 높음 → 관대 → false reject 감소
            - 대부분 0.5 ~ 0.7
