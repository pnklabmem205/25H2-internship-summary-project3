# v0.7 설계 (출입 기록 DB 연동)

## 1. 목표

- ESP32 얼굴 인식 디바이스에서 **인증 로직은 로컬에서 그대로 수행**
- 인증이 **성공으로 확정되는 시점**에만 서버로 HTTP 요청을 보내서
    - **출입 로그를 서버 DB(`access_logs`)에 1건씩 저장**
- 서버는 **출입 로그 수집·조회만 수행**
- 관리자 웹 UI에서
    - 얼굴 등록/삭제/리스트는 ESP32 로컬 기능을 사용하고
    - **출입 로그 탭에서 서버의 출입 로그를 조회**할 수 있도록 함

---

## 2. 전체 시스템 구성 개요

### 2.1 디바이스(ESP32) 측 개요

- 기반: `esp-who / examples / human_face_recognition`
- 주요 역할
    - 카메라 프레임 캡처 (`WhoS3Cam`)
    - 얼굴 검출 + 임베딩 추출 (`FaceProcessor`)
    - 로컬 얼굴 DB(`/spiflash/faces.bin`)과 임베딩 매칭
    - 인증 상태머신 (`AuthState`, `AuthStateMachine`)
    - 인증 상태에 따라 LED 제어 (`AuthLed`)
    - 인증 **성공 시** 출입 로그를 서버로 POST (`FaceHttp` 모듈)
    - 내장 HTTP 서버:
        - `/` : 관리 UI (등록/삭제/리스트/출입로그 탭)
        - `/stream` : 얼굴 박스 오버레이 MJPEG 스트림
        - `/register` : 현재 프레임에서 얼굴 등록
        - `/faces` : 로컬 얼굴 목록(JSON)
        - `/face_delete` : 얼굴 삭제
        - `/snapshot` : 단일 JPEG 스냅샷 (디버깅용)

---

### 2.2 서버 측 개요

- 프레임워크: **FastAPI**
- DB: PostgreSQL
- ORM: **SQLAlchemy**
    - ORM: 객체(Object)와 관계형 데이터베이스(Relational DB)를 잦동으로 연결해주는 기술
    - SQLAlchemy: Python 에서 가장 널리 쓰이는 ORM 라이브러리
- 제공 API
    - `POST /api/access-logs`
        - ESP32에서 인증 성공 시 전송하는 출입 로그 수신
        - body: `device_id`, `event_time`, `result`, `face_id`, `face_name`, `similarity`
        - 동작: DB `access_logs`에 1건 insert
    - `GET /api/access-logs`
        - 최근 출입 로그 목록 반환
        - 관리자용 웹 UI가 이 엔드포인트를 호출해 **출입 로그 탭**을 렌더링

---

### 2.3 서버 폴더 구조 및 역할

현재 서버 루트: `esp-who-server/`

```
app/
 ├── api/
 │    └── access_logs.py
 ├── core/
 │    └── config.py
 ├── db/
 │    └── session.py
 ├── models/
 │    └── access_log.py
 ├── schemas/
 │    └── access_log.py
 └── main.py  
.env
```

- 파일 상세 설명
    
    ### `app/main.py`
    
    - FastAPI 애플리케이션을 생성하는 진입점
    - 주요 역할:
        - `init_db()`로 테이블 생성 (`Base.metadata.create_all`)
        - CORS 설정 (ESP32, 브라우저 둘 다 접근 가능하게 허용)
        - `access_logs` 라우터 등록:
            
            ```python
            app.include_router(access_logs.router)
            ```
            
    
    ### `app/core/config.py`
    
    - `.env`에서 환경 변수를 읽어오는 설정 모듈
    - 예:
        - `DATABASE_URL`
        - `ENV` / `DEBUG` 플래그
    
    ### `app/db/session.py`
    
    - SQLAlchemy 엔진과 세션 팩토리, `Base`를 정의
        - `engine = create_engine(settings.DATABASE_URL, ...)`
        - `SessionLocal = sessionmaker(...)`
        - `Base = declarative_base()`
    - FastAPI 의존성으로 세션을 주입할 때 사용:
        
        ```python
        def get_db():
            db = SessionLocal()
            try:
                yield db
            finally:
                db.close()
        ```
        
    - 모든 모델(`AccessLog`)은 이 `Base`를 상속
    
    ### `app/models/access_log.py`
    
    - DB 테이블 `access_logs` 에 대응하는 SQLAlchemy 모델 정의
    - 설계 의도:
        - DB에 어떤 컬럼을 저장할지, 타입과 제약을 코드로 명시
        - FastAPI 라우터에서 ORM 객체를 사용해 insert / query 수행
    
    ### `app/schemas/access_log.py`
    
    - 요청/응답에서 사용하는 데이터 구조 정의
        - `AccessLogCreate`
            - ESP32에서 `POST /api/access-logs`로 보내는 body 형식
        - `AccessLogItem`
            - `GET /api/access-logs`에서 반환하는 각 행의 형식
            - `event_time_kr`(한국 시간 문자열)을 포함해 클라이언트가 바로 표시 가능하게 설계
    - 설계 의도:
        - API 입출력 규격을 타입으로 고정함으로써 ESP32와 서버 양쪽의 인터페이스를 명확하게 관리
    
    ### `app/api/access_logs.py`
    
    - FastAPI 라우터를 담당하는 모듈
    - 주요 엔드포인트:
        1. `POST /api/access-logs`
            - body: `AccessLogCreate`
            - 동작:
                - 요청 데이터를 `AccessLog` ORM 인스턴스로 변환
                - DB에 `insert` 후 commit
                - 필요 시 `id`, `event_time` 등 반환
        2. `GET /api/access-logs`
            - 쿼리: 최근 N개 (예: 50개) 조회
            - DB `AccessLog` 역순 정렬 후 리스트로 가져옴
            - 각 row를 `AccessLogItem`으로 변환하면서
                - `event_time` → KST(`UTC+9`) 변환
                - 사람이 보기 좋은 문자열 `event_time_kr` 생성
            - JSON 배열 응답
    - ESP32 내장 웹 UI의 “출입 로그” 탭에서 이 파일의 엔드포인트를 직접 호출

## 3. 데이터 흐름

### 3.1 인증 성공 시 출입 로그 저장

1. 사용자가 카메라 앞에 서면, ESP32-CAM이 프레임 캡처
2. `FaceProcessor`가 얼굴을 검출하고, 임베딩(512-dim) 계산
3. 로컬 Face DB(`/spiflash/faces.bin`)와 비교해 가장 유사한 얼굴 선택
4. 유사도가 threshold 이상이고 몇 프레임 연속으로 유지되면
    
    `AuthStateMachine`에서 상태를 `AUTH_SUCCESS` 로 전환
    
5. `AUTH_SUCCESS`가 발생한 시점에:
    - ESP32에서 출입 로그 JSON 생성:
        
        ```json
        {
          "device_id": "LAB",
          "event_time": "<ESP 기준 현재시각>",
          "result": "SUCCESS",
          "face_id": 0,
          "face_name": "yh",
          "similarity": 0.78
        }
        ```
        
    - `FaceHttp` 모듈이 `POST http://<SERVER_IP>:8000/api/access-logs` 호출
6. 서버 `access_logs` API:
    - body를 `AccessLogCreate`로 검증
    - `AccessLog` ORM 객체로 변환 후 DB에 insert

---

### 3.2 출입 로그 조회 (ESP UI → 서버)

1. 브라우저에서 ESP32 IP로 접속 → 내장 페이지 로딩
2. 상단 탭에서 **“출입로그”** 버튼 클릭
3. 페이지 내 JS 함수 `fetchAccessLogs()` 실행:
    - `GET http://<SERVER_IP>:8000/api/access-logs` 요청
4. 서버:
    - `access_logs` 테이블에서 최근 N개 행 조회 (event_time 기준 내림차순)
    - 각 행에 대해:
        - DB에 저장된 `event_time`을 기준으로 한국 시간(KST) 변환
        - `"YYYY-MM-DD HH:MM:SS"` 형식의 `event_time_kr` 문자열 생성
    - JSON 배열로 반환:
        
        ```json
        [
          { "id": 50, "face_name": "yh", "event_time_kr": "2025-12-04 10:00:00" },
          ...
        ]
        ```
        
5. 브라우저:
    - 응답 배열을 테이블에 렌더링
    - 상단 상태 영역에 `"최근 N건"` 표시

## 4. DB 테이블 구성

### `access_logs` 테이블

| 컬럼명 | 타입 | 예시값 | 설명 |
| --- | --- | --- | --- |
| `id` | `Integer`, PK, Auto Increment | `50` | 로그 고유 ID |
| `device_id` | `String`  | `"LAB"` / `"DOOR_01"` | 출입 장치 ID (문/게이트 단위 식별자) |
| `event_time` | `DateTime(timezone=True)` | `2025-12-04 01:00:00+00:00` | 사건 발생 시각 |
| `result` | `String` | `"SUCCESS"` / `"FAIL"` | 인증 결과 상태 |
| `face_id` | `Integer`, Nullable | `0` 또는 `NULL` | 로컬 face index  |
| `face_name` | `String`, Nullable | `"yh"` / `NULL` | 로컬에 등록된 이름 |
| `similarity` | `Float`, Nullable | `0.78` | 매칭 유사도 (0.0~1.0) |
