## 1. 사용 라이브러리

- **FastLED** → WS2812 네오픽셀 제어

## 2. WS2812 (네오픽셀) 핵심 사양 요약

1. **제품 구성**: WS2812 칩 내장 5050 RGB LED × 8개, 링 형태
2. **전원**: 5V DC 공급
3. **제어 방식**: 단일 데이터선 (DIN → DO → 연쇄 연결 가능), 800 kHz 신호
4. **색상 표현**: LED당 24 비트 (8비트 R/G/B 각), 약 1,670만 색 표현 가능
5. **물리 크기 (일반 예시)**: 외경 약 32 mm, 내경 약 18 mm
6. **소비 전류 (최대 밝기 백색 기준)**: LED 하나당 약 50–60 mA
    
    → 8개 모두 밝게 켜면 최대 약 400–480 mA 필요
    
    (USB 5V만으로는 어려울 수 있을 거라 예상 )
    

## **3. WS2812 네오픽셀 LED 기능 정리**

1. **개별 제어 가능**
    - 각 LED가 독립적으로 색(RGB)과 밝기를 가질 수 있음 → 예: 무지개 패턴, 애니메이션 효과 등 가능
2. **24bit 컬러 표현**
    - 각 LED: R(0~255), G(0~255), B(0~255) → 약 1,670만 가지 색 표현 가능
    - `CRGB::White` (미리 정의된 색), `CRGB(r, g, b)` (직접 RGB 값), `CHSV(h, s, v)` (HSV 방식)
        - `CRGB::White` = 빨강, 초록, 파랑을 모두 255로 채운 상태 → 순수 흰색
        - `CRGB::Black` = R=G=B=0 → 꺼진 상태
3. **밝기 제어 가능**
    - 전체 밝기(`FastLED.setBrightness(0~255)`)
    - LED별 밝기(`CRGB(r,g,b)` 값 자체로 조절)
4. **패턴/애니메이션 지원**
    - 웨이브, 깜빡임, 무지개, 색상 전환 등 구현 가능
    - FastLED/Adafruit_NeoPixel 라이브러리가 제공
5. **상태 유지 특성**
    - 한 번 색을 설정하면, 전원이 유지되는 동안 계속 같은 색/밝기를 유지함
    - MCU가 신호를 더 안 줘도 꺼지지 않음

## 4. 이번 프로젝트에서의 사용 방식

- **색상**: `CRGB::White` (순백색)
- **LED 개수**: 8개 (`NUM_LEDS = 8`)
- **밝기**: 낮음 (`LED_BRIGHT = 20~60` 권장, 센서 포화 방지)
- **패턴 제어**: 필요 없음 → 한 번 흰색으로 세팅해두고 계속 유지

## 5. FastLED 기본 속성 지정

```cpp
#incldue <FastLED.h>

#define LED_PIN       8      // WS2812 DIN에 연결한 ESP32 GPIO
#define NUM_LEDS      8      // 링 LED 개수
#define LED_BRIGHT    40     // 전체 밝기 (0~255)

CRGB leds[NUM_LEDS];        // LED 색상 데이터 저장용 배열
```

## 6. `initColorSensor()` 변경된 부분 (colorsensor.cpp)


## TCS34725 블랙/화이트 캘리브레이션 정리

### 내가 놓친 점

- 지금까지 **블랙 캘리브레이션도 화이트 캘리브레이션과 같은 환경(LED ON 상태)** 에서 진행
- 그 결과 **“진짜 암부(0점)” 기준**이 아닌 **빛이 들어온 상태 기준**이 블랙 값으로 저장됨
- 실제 검은색을 회색처럼 인식 → 측정 정확도가 떨어짐

---

### 개선한 점

- 코드에서 **블랙 캘리 시**:
    - 센서 내장 LED **OFF**
    - WS2812 링 LED **OFF**
- **화이트 캘리 시**:
    - 센서 내장 LED **ON**
    - WS2812 링 LED **ON**
- 블랙/화이트 각각 **환경 분리**하여 진짜 “0점 / 100점” 기준 잡도록 수정

---

### 📌 블랙 캘리브레이션

- **목적**: 센서가 빛이 없을 때 나오는 **잔여값(노이즈/오프셋)** 기록
- **환경**:
    - 센서 LED: OFF
    - WS2812 링 LED: OFF
- **이상적 Clear(C) 값**: 0 ~ 2000 (5천까지는 허용)

---

### 📌 화이트 캘리브레이션

- **목적**: 센서가 최대 밝기일 때의 **기준점(스케일링 상한)** 기록
- **환경**:
    - 센서 LED: ON
    - WS2812 링 LED: ON (또는 둘 중 하나)
    - 흰 종이나 흰색 기준 타겟을 센서 가까이 대기
- **이상적 Clear(C) 값**: 40,000 ~ 58,000 (65,535의 60~90%)

---

## 최종 정리

- 블랙 = **0점(Offset)**
- 화이트 = **100점(Scale)**
- 이 두 값을 기반으로, 측정 RGB를 **0~255** 범위로 보정하면 측정 색 정확도를 크게 향상 시킬 수 있을거라 예상

### 캘리브레이션 위한 LED 2종 ON/OFF

---

- **센서 내장 LED**: `SENSOR_LED_PIN`(GPIO9)로 제어
- **WS2812 링 LED**: FastLED로 제어 (DIN=GPIO8, 8개, 밝기=200)
- **블랙 캘리**: **둘 다 OFF**
- **화이트 캘리 & 측정**: **둘 다 ON** (필요 시 변경)

## 1. 코드 핵심 (colorsensor.cpp)

### 1-1. 핀/밝기 설정

```cpp
// I2C
#define SDA_PIN 4
#define SCL_PIN 5

// 센서 보드 내장 LED (Active-High 가정: HIGH=ON, LOW=OFF)
#define SENSOR_LED_PIN 9

// WS2812 링
#define LED_PIN    8
#define NUM_LEDS   8
#define LED_BRIGHT 200
```

### 1-2. WS2812 제어

```cpp
CRGB leds[NUM_LEDS];

void turnLedOff() { // WS2812 OFF
  fill_solid(leds, NUM_LEDS, CRGB::Black);
  FastLED.show();
}

void turnLedWhite() { // WS2812 ON
  fill_solid(leds, NUM_LEDS, CRGB::White);
  FastLED.show();
}
```

### 1-3. 센서 LED 제어 (Active-High)

```cpp
void initSensorLed() {
  pinMode(SENSOR_LED_PIN, OUTPUT);
  digitalWrite(SENSOR_LED_PIN, HIGH);  // 기본 ON
}

void sensorLedOn()  { digitalWrite(SENSOR_LED_PIN, HIGH); }  // ON
void sensorLedOff() { digitalWrite(SENSOR_LED_PIN, LOW);  }  // OFF

```

### 1-4. 초기화에서 LED 준비

```cpp
void initColorSensor() {
  Wire.begin(SDA_PIN, SCL_PIN);
  if (!tcs.begin()) { Serial.println("[TCS34725] Not found!"); while(1) delay(1000); }
  Serial.println("[TCS34725] Found.");
  tcs.setGain(TCS34725_GAIN_4X);
  tcs.setIntegrationTime(TCS34725_INTEGRATIONTIME_154MS);

  FastLED.addLeds<WS2812B, LED_PIN, GRB>(leds, NUM_LEDS);
  FastLED.setBrightness(LED_BRIGHT);

  **initSensorLed();   // 센서 LED 초기화(기본 ON)
  turnLedWhite();    // 링 LED 흰색 ON
  sensorLedOn();     // 내장 LED ON**
}
```

### 1-5. 블랙/화이트 캘리 (측정 로직은 기존 그대로)

- **블랙 캘리**: 조명 모두 끄고 측정(오프셋)
- **화이트 캘리**: 조명 켜고 안정화 후 측정(스케일링 상한)

- c 값이 최대 값인 65535와 너무 가까우면 포화 위험이 있기 때문에 30000~50000 을 목표로 해야 함

    - `rWn=10413, gWn=24830, bWn=34462, cw=63835`
        
        → 이건 센서의 **원시값(16bit)** 평균
        
    - `WHITE 8bit r=40 g=96 b=134`
        
        → `rWn/65535*255` 같은 **절대 스케일**로 찍은 것뿐
        
    - 실제 측정에서는 `readRgb8ForBle()`에서
        - 블랙 오프셋 제거 후,
        - 화이트 기준으로 나눠서( r_corr / g_rWn 등 ) **×** 255,
        - 또 `bf = sqrt(c/cw)` 밝기 인자까지 곱해 **정규화**
            
            → 같은 조건에서 다시 읽으면 화이트는 (255, 255, 255) 근처가 나오게 됨
            
- 값이 낮게 나오는 것의 문제가 아니라 `40/96/134`는 **스펙트럼(LED가 파·초록이 강함) 때문에 채널별 원시 값이 다르다**는 걸 보여주어 ****최종 색 rgb 값이 다를 수 있다는 것을 깨달음
    - **센서 내장 LED + WS2812 링** 둘 다 켜서 화이트 캘리 중이라면, 광원이 차갑게(Blue/Green) 치우쳐**R 원시값이 낮게** 잡힐 수 있음
    - 실사용에선 한 쪽만 쓰거나, 밝기/거리로 균형 맞춰야 한다고 함
    - 실제 눈으로 보기에도 센서 내장 LED 와 WS2812 링의 색 차이가 들어남 → 센서 내장 LED를 아예 끄고 test를 진행 해봐야겠다고 생각

## Test2: WS2812 LED (#define LED_BRIGHT    180)

- #define LED_BRIGHT 값을 200→180 으로 설정
- 센서 내장 LED를 OFF 한 후, WS2812 백색 LED로만 test

![image.png](attachment:ac9e0a25-7aeb-42c7-8c57-39398f22f23e:image.png)

<화이트 캘리브레이션>

Clear(c) = 52518.0

- Clear(c) 값은 #define LED_BRIGHT 값을 200 으로 설정했을 때보다 내려갔지만 조금 더 줄여도 될 거 같음
- 센서 내장 LED를 OFF 했음에도 `30/80/112` 처럼 **스펙트럼(LED가 파·초록이 강함) 때문에 채널별 원시 값이 다른가?** 의 의문점은 해결되지 않음
    - `CRGB::White (R=255,G=255,B=255)` 말고 각 RGB 값을 지정해서 LED를 켜보면 어떨까 하고 GPT에 물어봤는데 LED 자체를 조정할 필요는 전혀 없다고 함
        1.  **센서 측정값 ≠ LED 색상 “정확히 255,255,255”**
        - TCS34725 같은 컬러 센서는 **채널별 감도**가 다름
            
            → 청색 채널이 상대적으로 민감하면, 같은 밝기의 화이트 LED를 켰어도 B 값이 크게 나옴
            
        - 실제 LED가 CRGB::White (R=255,G=255,B=255)라고 해도, 센서가 보는 값은 **R<G<B**처럼 나올 수 있음
        
        즉, **센서가 느끼는 밝기와 LED 입력 RGB 값은 1:1 대응이 아님**.
        
        ---
        
        1. **화이트 캘리 목적**
        - 화이트 캘리는 **센서가 보는 최대 값**을 기록하는 것이 목적
        - R/G/B 값이 균등하게 나오길 바라는 게 아니라, **각 채널별 최대값을 기준으로 8bit 스케일링**을 하는 것임
        - `readRgb8ForBle()`에서:
            
            ```cpp
            rF = (r_corr / g_rWn) * 255
            gF = (g_corr / g_gWn) * 255
            bF = (b_corr / g_bWn) * 255
            ```
            
            →  **채널 별 화이트 기준 비율 조정**이 적용됨
            
        
        ---
        
    - 즉, LED 자체 RGB 조정은 **필요 없음**
    1. LED가 흰색이든 조금 파란끼가 있든 상관 없음
    2. 캘리값 `g_rWn/g_gWn/g_bWn`를 **각 채널별 최대값**으로 기록하고
    3. 측정값을 8bit로 변환할 때 **비율로 보정**되므로 최종 8bit RGB는 LED 색상 균형과 무관하게 안정적임
    - 만약 LED 색상 자체를 맞춰서 센서 값이 **R≈G≈B**가 되도록 한다면, 센서 raw 값이 균일하게 나오지만 → 결국 `readRgb8ForBle()`에서 다시 스케일링하기 때문에 크게 의미 없음

## 2. Gain (증폭)

- 의미: 센서 출력 전압 증폭
- 현재: `TCS34725_GAIN_1X`
- 특징:
    - 낮은 Gain → 밝은 환경에서 포화 방지
    - 높은 Gain → 어두운 색 측정 정확도 향상
- 추천:
    - 밝은 환경 → 1X~4X
    - 어두운 환경 → 16X까지 사용 가능
