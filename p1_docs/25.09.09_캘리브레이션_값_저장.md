## 1️⃣ RAW RGB를 그냥 읽기 힘든 이유

TCS34725 같은 컬러 센서는 **빛을 전기 신호로 바꾸는 센서**

 RAW 데이터를 그대로 읽으면 다음 문제들이 생김:

| 문제 | 이유 |
| --- | --- |
| **조명 환경에 민감** | 실내 조명, 햇빛, LED 색 온도에 따라 값이 달라짐 |
| **센서 잡음 존재** | 완전히 어두워도 센서가 작은 값(잡음)을 읽음 |
| **색상 왜곡** | 센서마다 R/G/B 감도가 다르고, 광학 필터 특성이 완벽하지 않음 |
| **포화 문제** | 너무 밝으면 최대값(65535)에 도달 → 실제 색상 구분 불가 |

즉, RAW RGB 값은 **그 자체로 의미 있는 색상값이 아님**

그냥 쓰면 환경마다 값이 크게 달라지고, 피부색이나 컬러카드 측정이 정확하지 않음

## 2️⃣ 캘리브레이션을 해야 하는 이유

캘리브레이션은 **센서값을 현실의 색상과 맞추기 위한 보정 과정**

### 2-1. 블랙 캘리브레이션 (Black Calibration)

- **목적:** 센서 잡음 제거
- **방법:** 센서를 덮거나 어두운 환경에서 여러 번 측정 → 평균값 저장
- **결과:** 실제 어두운 색이 0 근처로 보정됨

### 2-2. 화이트 캘리브레이션 (White Calibration)

- **목적:** 밝기와 R/G/B 비율 정규화 → 조명 변화 보정
- **방법:** 화이트 타겟(컬러카드 흰색 등)을 여러 번 측정 → R/G/B 대비 화이트 비율 계산
- **결과:** 밝기와 조명 영향 없이 상대적 색상값 확보

- BUT, 테스트 할 때마다 흰 색 카드 찍는 건 번거로움

### 🔧 방법 1: **레퍼런스 흰색값 저장**

- 한 번 흰색 카드 찍어서 나온 값(R, G, B, Clear)을 저장해 둔다.
- 이후 테스트에서는 그 값을 **기준값(화이트 포인트)**으로 계속 사용.
- 단, 조명/환경이 달라지면 값이 달라질 수 있어서 정밀 테스트 때만 다시 찍어주면 됨.

---

### 🔧 방법 2: **상대값(비율)만 사용**

- 흰색 캘리브레이션 대신 “상대 비율”만 활용하는 방법.
- 예: `(R / (R+G+B)), (G / (R+G+B)), (B / (R+G+B))` → 조명 강도 차이를 줄일 수 있음.
- 이러면 절대값 보정이 필요 없어져서 매번 화이트 캘리브레이션을 안 해도 됨.

---

### 🔧 방법 3: **실험 환경 고정**

- 테스트하는 동안 조명·센서 위치를 최대한 고정하면 → 한 번만 캘리브레이션 해도 여러 번 테스트 가능.

TCS34725 센서는 **Integration Time(적분 시간)** 동안 빛을 모아서 값을 읽습니다.

- 예를 들어 Integration Time이 154ms라면, 센서는 **약 0.154초 동안 들어오는 빛을 쭉 모아 평균값**을 만들어 측정합니다.
- 이 시간이 지나야 **정확한 측정값**이 나오죠.

그런데 지금 코드에서는 `wait_ms = 40`으로 되어 있어요.

- 즉, **센서가 데이터를 다 모으기 전에 40ms만 기다리고 다음 측정**으로 넘어감
- 결과적으로 측정값이 **불안정하거나 낮게 나올 수 있음** → 평균값에도 영향을 줌

그래서 **wait_ms를 Integration Time 이상, 예를 들어 200ms 정도로 잡아야 안정적인 값**을 얻을 수 있습니다.

간단히 말하면:

> 센서가 “빛을 충분히 모으는 시간”보다 빨리 측정하면 값이 흔들림 → wait_ms를 Integration Time 이상으로 늘려야 함
> 

---

즉, **샘플 수(samples)는 충분히 평균을 낼 수 있도록 하고, 측정 간격(wait_ms)은 센서가 빛을 다 모을 수 있는 시간 이상**으로 잡아야 안정적입니다.

### 1.  블랙 캘리브레이션

- **하는 일**: 빛이 전혀 없는 상태(센서 덮음, 검은 표면 측정)에서 값이 얼마나 나오는지 확인
- **이유**: 센서가 전기적 잡음이나 주변광 때문에 "0이 아닌 값"을 낼 수 있어서, 그 오차를 빼주기 위해 필요
- **효과**: 센서의 **최소값(0%) 기준점** 설정
- **로직**:
    - **센서를 가려서(또는 블랙 표면)** 빛이 거의 없는 상태에서 RGB 값을 읽음
    - 이 값은 **센서가 기본적으로 갖는 오프셋(잡음)**
    - 이후 실제 측정값에서 이 오프셋을 빼줌

- **이유**: 각 채널(R/G/B)의 최대 밝기 응답 차이를 보정하고, 측정치를 상대적인 비율(0~100%)로 바꾸기 위해 필요
- **효과**: 센서의 **최대값(100%) 기준점** 설정
- 로직:
    - **흰 기준면(예: 흰 종이)** 을 센서에 대고 RGB 값을 읽음
