# 프로젝트 정의

# 📌 프로젝트: 피부톤 특화 컬러센서 보정 실험

---

## 1. **프로젝트 개요**

- **최종 목표**: 피부 진단 및 개인 맞춤 서비스를 위한 **피부톤 특화 컬러센서 측정기 제작**
- **핵심 아이디어**:
    - 기존 → 모든 색상 일반화 보정
    - 개선 → **피부톤 중심 보정(CCM)** 으로 전환 → 실제 활용성↑

---

## 2. **연구 배경 & 필요성**

- 센서 원본 출력값은 **환경·하드웨어 보정(케이싱, LED 등)** 이후에도 여전히 오차가 큼
- 피부 진단, 맞춤형 화장품·의료 서비스에서는 **정확한 피부톤 인식이 핵심**
- 따라서 **스킨톤 중심 데이터셋 & 보정 모델** 필요

---

## 3. **연구 목표**

- **평균 오차율(MAE_avg)** ≤ **10**
- **±10칸 성공률** ≥ **80%**
    - (±10칸 ≈ 0~255 스케일에서 ±4% 오차 허용)

---

## 4. **데이터 전략**

- **대표색 100개** 선정
    - 중심: 피부톤(밝/중/어두운 피부 × 웜/뉴트럴/쿨 = 9 버킷)
    - 보조: 저채도 주변색(그레이, 흰/검, 중성 보정용) 포함
- **단계적 학습 진행**
    1. **1차**: 20개 훈련 / 나머지 검증
    2. **2차**: 20 + 40 (=60) 훈련 / 나머지 검증
    3. **3차**: 20 + 40 + 20 (=80) 훈련 / 나머지 검증

---

## 5. **측정 프로토콜**

- **반복 측정**: 색당 **10회 측정 → 평균값 사용**
- **측정 방식 개선**:
    - 기존: 센서를 고정 → 한 지점만 반복 측정
    - 개선: **같은 패치의 여러 부분**을 측정 → 평균값 → 더 공정하고 신뢰성↑

---

## 6. **하드웨어/광학 세팅**

**A. 현재 세팅**

- 케이싱(4차 버전)
- WS2812 LED 단일 모듈 (4개)
- 노출: ATIME 700ms, GAIN 16×

**B. 개선 세팅**

- **LED 추가/광량 증대** → 더 안정적 신호 확보
- **ATIME × GAIN 매트릭스** 실험 → 최적 노출 찾기
- 동일 조건으로 훈련/검증 반복 → **효과 비교**

---

## 7. **모델/보정 고도화 (스킨톤 중심)**

- 전체 색상 보정보다는 **피부톤 정확도 최적화**
- 스킨톤 영역에서 오차가 최소화되도록 CCM 적용

---

## 8. **지표 & 목표**

- **평가 지표**
    - MAE_avg (평균 오차율)
    - ±10칸 성공률 (사용자 체감 기준)
- **최종 목표**
    - MAE_avg ≤ 10
    - ±10칸 성공률 ≥ 80%

4. **단계별 훈련/검증** (20 → 60 → 80)

## 1) RGB → HSV로 바꿔 피부톤 분류

- RGB(빨강, 초록, 파랑) 값만 보면 색의 느낌(웜/쿨, 밝기, 채도)을 직관적으로 알기 힘들기 때문에 **HSV**(Hue, Saturation, Value)로 변환해서 분류
    - **Hue(H, 색상각)**
        - 0°~360° 범위, 색의 기운(빨강·노랑·초록·파랑…)
        - 예) H=0° → 빨강, H=120° → 초록, H=240° → 파랑
    - **Saturation(S, 채도)**
        - 0~1 범위, 색의 쨍한 정도
        - 0이면 회색, 1이면 원색
    - **Value(V, 밝기)**
        - 0~1 범위, 색의 밝은 정도
        - 0이면 완전 검정, 1이면 완전 흰색
- 변환 과정:
    1. RGB(0–255)를 0–1 범위로 변환 
        
        예: (R,G,B) = (230, 200, 180) → (0.90, 0.78, 0.71)
        
    2. R,G,B 중 **최댓값(M), 최솟값(m)** 구함
        
        예: (0.90, 0.78, 0.71) → M=0.90, m=0.71, diff=0.19 (diff는 차이)
        
    3. **Value (V, 밝기)**  → 밝/중/어두움 구분에 사용
        - **V = M (최댓값)**
        - 즉, RGB 중에서 제일 큰 값이 밝기(Value)
        - 위 예시 → V = 0.90
    4. **Saturation (S, 채도)**  → 피부톤은 보통 **저채도**
        - **S = diff / M** (단, M=0이면 S=0)
        - 색이 얼마나 “쨍한지”
        - diff가 클수록 → 원색에 가깝고 채도 높음
        - diff가 작을수록 → 회색/탁한색
        
        예: diff=0.19, M=0.90 → S = 0.19/0.90 ≈ 0.21
        
    5. **Hue (H, 색상각도)**  → 웜/뉴트럴/쿨 구분에 좋음
        - 색의 종류(빨강, 초록, 파랑)를 각도(0°~360°)로 표현
        - 계산 규칙 (누가 최댓값인지에 따라 달라짐):
            - R이 최댓값일 때:
                
                $H = 60 × \frac{(G−B)}{diff}$
                
            - G가 최댓값일 때:
                
                $H = 60 × \frac{(B−R)}{diff} + 120$
                
            - B가 최댓값일 때:
                
                $H = 60 × \frac{(R−G)}{diff} + 240$
                
        - 계산 후, H<0이면 360을 더함
        
        예: R=0.90, G=0.78, B=0.71 → R이 최댓값
        
        H = 60 × (0.78−0.71)/0.19 ≈ 22°
        
        → 오렌지색 계열
        
    
    ![image.png](attachment:71e90394-e890-4583-9e2d-2cf70bc0bff8:image.png)
    
    | Hue(°) | 대표 색상 | 설명 |
    | --- | --- | --- |
    | **0°** | 빨강 (Red) | 기준점, 순수 빨강 |
    | **30°** | 주황 (Orange) | 빨강+노랑 섞인 느낌 |
    | **60°** | 노랑 (Yellow) | 선명한 노란색 |
    | **90°** | 연두 (Yellow-Green) | 노랑과 초록 사이 |
    | **120°** | 초록 (Green) | 순수한 초록색 |
    | **150°** | 청록 (Yellow-Cyan) | 녹색+하늘색 |
    | **180°** | 시안 (Cyan/하늘) | 파랑과 초록 중간, 하늘색 |
    | **210°** | 청파랑 (Blue-Cyan) | 청록+파랑 중간 |
    | **240°** | 파랑 (Blue) | 순수한 파란색 |
    | **270°** | 남보라 (Blue-Magenta) | 파랑+보라 사이 |
    | **300°** | 보라/자홍 (Magenta) | 보라/핑크 계열 |
    | **330°** | 핑크-빨강 (Rose) | 빨강+보라 섞인 장밋빛 |
    | **360°** | 빨강 (Red) | 다시 처음으로 돌아감 |
    

## 2) 피부톤 후보 필터 (원색/극단 값 제거)

- 참고 문헌: https://patents.google.com/patent/KR20200113853A/ko
    
    ![image.png](attachment:d419f333-4b37-454f-b5cb-e1ce4278b132:0e919a70-ab92-42b8-adfd-9fadf4ebe192.png)
    
    - 영상처리에서 많이 쓰이는 조건
        - 채도(S)가 0.2 이상 / Hue가 빨강~주항 영역 / 밝기 대비 채도가 적절히 균형 잡혀야 함
    - 영상처리(카메라)는 조명, 그림자, 배경 등 변수가 많아 피부만 뽑기 위해서는 조건을 엄격하게 잡음
    - 영상처리용 조건을 그대로 쓰면 피부 후보가 빠질 수 있음
    - 센서 기반 측정은 비교적 고정된 환경과 조명 세팅 등으로 안정적인 값 확보가 가능하기 때문에 조건을 좀 더 완화하여 피부톤 분포를 최대한 포괄하는게 목표

### 1. **밝기(V) 조건**

- `0.15 ≤ V ≤ 0.98`
- 너무 어둡거나(0.15↓) 너무 밝은(0.98↑) 값은 피부로 보기 힘듦
- 어두운 피부(흑인)도 포함할 수 있게 **0.15**
- 밝은 피부(백인)도 포함할 수 있게 **0.98**

---

### 2. **채도(S) 조건**

- `S ≤ 0.65`
- 피부는 원색처럼 쨍하지 않고, 채도가 낮은 편

---

### 3. **Hue(색상각) 조건**

- `H ∈ [0°, 60°] ∪ [300°, 360°]` → 웜톤/핑크~노랑 계열
- `H ∈ [50°, 140°]` → 뉴트럴/올리브 계열
- `H ∈ [140°, 300°]` → 쿨톤
- **즉, 피부가 나올 수 있는 Hue 범위 전체 허용**

---

### 4. **R 성분 조건**

- `R ≥ G − 50 AND R ≥ B − 50` (R이 최소한 가장 큰 채널이어야 함)
    - 멜라닌, 헤모글로빈 같은 피부 성분 때문에 **피부색은 완전히 초록·파랑 계열로 치우치지 않음**
    - **G(초록)** 이 제일 크면 → 초록/연두 계열 (풀, 배경, 옷감일 가능성 ↑)
    - **B(파랑)** 이 제일 크면 → 파랑/보라 계열 (하늘, 바다, 파란 카드 등)
    - 실제 사람 피부에서 이런 경우는 거의 없지만 흑인 등 어두운 피부를 위해 R이 다른 채널과 비슷한 경우를 포함함

### 2. 훈련/검증 반복

- **훈련:** 색상당 10샷 (Spot 5 × 2) → 중앙값 사용
- **검증:** 색상당 5샷 (Spot 5 × 1) → 중앙값 사용

---

### 3. 반자동 측정 흐름

- **보드 역할:** 측정은 항상 “1샷” 단위
- **PC 프로그램 역할:** 측정 안내 + 데이터 수집/계산
- **실행 순서:**
    1. PC가 `"Spot1 찍으세요"` 안내
    2. 사용자가 센서를 Spot1에 대고 **Enter** 입력
    3. PC가 보드에 `a` 신호 → 보드가 1샷 측정
    4. 결과가 PC로 전달되어 기록
    5. Spot2~Spot5까지 같은 방식 반복
    6. 각 Spot에서 2회씩 → 총 **10샷** 수집
    7. PC가 자동으로 **중앙값 계산** 후 최종 RGB 값 저장

👉 **장점:**

- 사용자가 센서를 옮기면서 여러 위치를 측정 가능
- 프로그램이 측정 흐름을 안내해줘서 실수 줄임
- 평균 대신 중앙값 사용 → 노이즈/오류값(outlier)에 강함

### 4. 랜덤 방식 (훈련/검증 분리)

- 전체 100색 중 단계적 훈련/검증
    - **1차:** 20 훈련 / 80 검증
    - **2차:** 60 훈련 / 40 검증
    - **3차:** 80 훈련 / 20 검증
- **층화 랜덤:** 버킷별 최소 수량 보장 + 나머지 랜덤
    
    
    | 버킷 | 1차 훈련 (20) | 2차 훈련 (60) | 3차 훈련 (80) |

    | Light-Warm | 2 | 6 | 8 |
    | Light-Neutral | 2 | 6 | 8 |
    | Light-Cool | 2 | 6 | 8 |
    | Medium-Warm | 2 | 6 | 8 |

    | Medium-Cool | 2 | 6 | 8 |

### 5. 실험 환경 고정

- 센서–카드 거리: **10 mm**
- 케이싱: **4차 버전 (LED/센서 관 고정)**
- 노출: **ATIME 700ms, GAIN 16×**
- LED 밝기: **WS2812 LED 일정값 고정 (255)**
- 순서: **Black 캘리브레이션 → White 캘리브레이션 → 대상 색**

---

### 6. 평가 지표

- **MAE_avg** (평균 오차율)
- **±10칸 성공률** (카드 RGB 대비 ±10)
