## A안 두번째 실험 계획

---

## 1. **실험 목표**

- 센서가 피부톤을 정확히 읽을 수 있도록 보정 모델(CCM)을 개선
- 최종 성능 지표:
    - **평균 오차율 (MAE_avg) ≤ 10**
    - **±10칸 성공률 ≥ 80%**
- 특히 어두운 톤(Dark) **G 채널 값**에서 발생하는 0값 문제(클리핑/언더샘플링)를 줄이는 것에 초점

---

## 2. **현재 상황**

- 사용 데이터: **100개 패치**
    - 피부톤 90개 (훈련/검증용)
    - 보정용 10개 (화이트·블랙·그레이)
- 훈련/검증 단계:
    - 20/80 → 60/40 → 80/20 순차 확장
- 모델: **3×4 CCM (bias 포함)**
- 결과:
    - 평균 오차율 약 **7% 수준**
    - 그러나 **Dark 영역 / G 채널**에서 값이 0으로 떨어지는 문제가 발생

---

## 3. **문제점**

1. **데이터 부족/불균형**
    - Dark(어두운 밝기) 영역의 패치가 적음
    - 일부 칸에 색이 몰려 분포 불균형 발생
2. **노출·광학 한계**
    - LED 광량 부족
3. **모델 단순성**
    - 전역 선형(3×4)만 사용 → 극단 상황(언더/클리핑) 보정 한계

---

## 4. **실험 설계**

### (A) 데이터 확장

- **200색 구성**
    - Dark 영역 각 칸 최소 **5개 이상**
    - Medium 각 칸 최소 **3개 이상**
    - Light 각 칸 최소 **2개 이상**
    - Hue 다양성 보장 (같은 칸에서도 색상각 ±15° 분산)
- **300색 구성**
    - Dark 영역 강화: 각 칸 최소 **7~8개 이상**
    - Medium ≥4, Light ≥3
    - Dark 비중을 전체의 **45~50% 수준**까지 확대
- 보정용 10색은 훈련/검증에서 제외, 세션 캘리브레이션 용도로만 사용

### (B) 훈련/검증 방식

- **층화 분할**: Tone × Brightness(Vbin) × Saturation(Sbin) 비율 유지
- **Train:Val = 85:15**
- 동일한 실험 프로토콜:
    - 색상당 10샷 → 중앙값 집계
    - Black/White 캘리브레이션 → 대상 색 순서 측정

### (C) 모델 비교

1. **3×4 + bias + 채널별 감마(γ 보정)**
2. **2차 다항(CCM²) + Ridge 정규화 + Huber 손실**
3. **구간별(piecewise) 3×4**
    - Light/Medium/Dark 각각 따로 행렬 계산

### (D) Dark/G 문제 대응

- **HDR 2노출 병합**: 짧은 노출 + 긴 노출 → 가중 평균
- **재측정 규칙**: 특정 채널 값이 ε 이하(예: <3)일 경우 재샷
- **전처리 정규화**: r=R/C, g=G/C, b=B/C + logC 추가 특징

---

## 5. **기대 효과**

- **100 → 200 패치**
    - 평균 오차율 5~10% 추가 개선
    - Dark/G=0 현상 일부 완화
- **200 → 300 패치**
    - Dark 영역 일반화 성능 강화
    - 극단 어두운 영역에서 0값 발생률 크게 감소
- 모델 개선 + HDR 병행 시 목표치(≤10, ≥80%) 근접 가능

## 피부톤 특화 실험 데이터 구성 방향 정리

## 1. 문제의식

- 처음에는 **100색 → 200색 → 300색**으로 패치 수를 늘리면 더 정확해질 거라 생각함
- 패치 수를 기존의 패치 수의 밝기나 채도 등 꼼꼼히 매우는 방식으로 늘려야 하는데
    
    이미 기존의 100색 패치의 조건 자체가 꼼꼼히 매우는 방식(조건)으로 설계 
    
- 단순히 패치 수를 늘리면:
    - **비피부 계열** (채도 높은 원색 등)이 데이터에 포함될 가능성 ↑
    - 결과적으로 **스킨톤 특화 목적**에서 벗어날 수 있음
        
        → 실제 200/300색에서는 채도가 높은 색들이 많이 포함되어 있음

## 2. 기존 100색의 장점

- **피부 후보 필터링** (HSV + R조건) → 스킨톤 가능 색만 추출
- **9버킷 균형 분배** (밝기×톤 3×3) → 대표성 확보
- Calibration 10개 포함 → 보정 기반 유지

→ 즉, 이미 피부톤 특화 데이터셋으로는 잘 설계되었다고 생각

---

## 3. 관찰된 한계

- **어두운 피부톤 측정에서 오차/G=0 문제**가 발생
- 단순히 전체 패치를 늘리는 건 오히려 잡음 색(비피부톤) 유입

---

## 4. 개선 방향

### 선택지

1. **200/300색 확장**
    - 장점: 데이터 다양성↑, 통계적 안정성↑
    - 단점: 스킨톤 특화 의미 희석, 비피부톤 혼입
1. **100색 유지 + Dark 비율 강화** 
    - 장점: 피부톤 특화 유지, Dark 문제 직접 해결
    - 방법: 기존 100색은 그대로 두고, Dark 버킷에서만 보강
1. **100색 + Dark 추가 패치 (110색, 120색 등)** 
    - 장점: 관리 간단, 기존 구조 유지하면서 Dark만 강화
