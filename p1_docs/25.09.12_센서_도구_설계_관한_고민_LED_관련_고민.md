## 2. 밝기 비율(bf) 계산 코드 수정

- 기존 rgb 변환 코드 (`colorsensor.cpp_readRgb8ForBle()`)
    - 센서 c_corr 값은 빛의 세기에 거의 선형적으로 반응하지만 인간의 눈은 선형적으로 느끼지 않고, 어두울 때는 민감하고 밝을 때는 둔감하게 반응(로그나 제곱근 곡선처럼)하기 때문에  “사람 눈으로 보는 느낌”과 더 가깝게 색을 정규화 하기 위해 **sqrtf()** 함수를 사용 했었으나 “사람 눈으로 보는 느낌”이 아니라 **“순수 측정 값”**을 계산하고 싶은 거기 때문에 **sqrtf() 함수를 제거해봐야겠다고 생각함**
    - bf 값 자체가 “환경이 바뀌었을 때(조명/거리 영향)” 색 비율만 유지하기 위해 쓰는 값인데, 현재는 케이싱을 통해 환경을 일정하게 세팅 해놨기 때문에 아예 **밝기 비율 계산 코드가 필요 없을 거라 생각함**
    
    ```jsx
    // 밝기 비율 계산 (화이트 대비) -> 현재 측정 밝기/최대 밝기(화이트캘리 상태)
    float bf = (g_cw > 1e-6f) ? **sqrtf**(c_corr / g_cw) : 0.0f;
    bf = clampf(bf, 0.0f, 1.0f);
    ```
    
- 수정 rgb 변환 코드 (`colorsensor.cpp_readRgb8ForBle()`)
    - 원래 코드는
    1. 블랙 보정(측정 값에서 블랙 캘리 값을 빼서 보정)
    2. 밝기 비율(bf) 계산
    3. 화이트 보정(현재 측정한 각 rgb 값이 자기 채널 최대치에 비해 몇 %인지)
    4. 0~255 범위 변환 후 출력
    - 수정된 코드는 밝기 비율(bf) 계산을 빼고
    1. 블랙 보정(측정 값에서 블랙 캘리 값을 빼서 보정)
    2. 화이트 보정(현재 측정한 각 rgb 값이 자기 채널 최대치에 비해 몇 %인지)
    3. 0~255 범위 변환 후 출력
    
    ```cpp
    void readRgb8ForBle(uint8_t &r8, uint8_t &g8, uint8_t &b8, uint16_t &cOut) {
        uint16_t R, G, B, C;
        tcs.getRawData(&R, &G, &B, &C);
    
        // 블랙 보정: 블랙 캘리 값을 빼서 0 기준으로 보정
        float r_corr = (float)R - g_r0; if(r_corr < 0) r_corr = 0;
        float g_corr = (float)G - g_g0; if(g_corr < 0) g_corr = 0;
        float b_corr = (float)B - g_b0; if(b_corr < 0) b_corr = 0;
        float c_corr = (float)C - g_c0; if(c_corr < 0) c_corr = 0;
    
        // 화이트 보정 (최대값 대비 스케일 정규화)
        float r_norm = (g_rWn > 1e-6f) ? (r_corr / g_rWn) : 0.0f;
        float g_norm = (g_gWn > 1e-6f) ? (g_corr / g_gWn) : 0.0f;
        float b_norm = (g_bWn > 1e-6f) ? (b_corr / g_bWn) : 0.0f;
    
        // 0~255 범위 변환
        r8 = (uint8_t)(clampf(r_norm, 0.0f, 1.0f) * 255.0f);
        g8 = (uint8_t)(clampf(g_norm, 0.0f, 1.0f) * 255.0f);
        b8 = (uint8_t)(clampf(b_norm, 0.0f, 1.0f) * 255.0f);
    
        // Clear 채널 값 그대로 반환 (밝기 참고용)
        cOut = (uint16_t)c_corr;
    }
    ```
    

### ✨ 빛 반사와 색상 측정 원리: 난반사 vs 정반사

- 빛이 물체에 닿으면 표면의 특성에 따라 두 가지 방식으로 반사
- 우리가 물체의 '색'을 인식하는 것은 이 중 **난반사** 때문

### **1. 난반사 (Diffuse Reflection)**

[diffuse reflection 이미지](https://encrypted-tbn3.gstatic.com/licensed-image?q=tbn:ANd9GcQSdh8u_3ewdDQK4xuVCNFZHb4MS-FOpue64B-jQCvFh1OhiAMhUHg_o6CsP1DEk_slK-OBMQTd5gRF7aWJxdiNEM7FR3HAV1f-n4cKMq-Dona5bCU)

- **개념**: 빛이 **거친 표면**에 부딪혀 사방으로 흩어지는 현상
- **원리**: 물체는 특정 색상의 파장만 반사하고 나머지 파장을 흡수. 이 반사된 파장이 우리 눈에 들어오면서 물체 고유의 색으로 인식
- **예시**: 종이, 옷감, 무광 페인트 등 **매트한 질감의 물체**에서 주로 발생. 우리가 어떤 각도에서 보든 물체의 색이 일정하게 보이는 이유가 바로 난반사 때문.
- **색상 측정과의 관계**: **난반사광**은 물체 자체의 색상 정보를 담고 있기 때문에, 정확한 색 측정을 위해서는 이 빛 만을 감지해야 함.

---

### **2. 정반사 (Specular Reflection)**

- **개념**: 빛이 **매끄러운 표면**에 부딪혀 거울처럼 한 방향으로 반사되는 현상
- **원리**: 빛의 입사각과 반사각이 동일한 반사의 법칙을 따름. 이 빛은 물체의 색상 정보가 아닌 **광원의 색상 정보**를 그대로 가지고 있음.
- **예시**: 거울, 유리, 광택 나는 금속이나 플라스틱 표면 등에서 발생하며, 눈부신 하이라이트(빛 반사)를 만들어 냄.
- **색상 측정과의 관계**: **정반사광**은 측정값을 왜곡시키는 주범. 이 빛이 센서로 유입되면, 센서는 물체 고유의 색(난반사)과 광원의 색(정반사)이 섞인 잘못된 값을 측정하게 됨.

---

### **💡 정확한 색상 측정을 위한 핵심**

- **정반사광 제거**: 정확한 색을 측정하려면 정반사광을 차단하고 난반사광만 받아들여야 합니다.
- **45/0 기하학적 배치**: 그래서 전문가들은 **빛을 45도 각도로 비추고, 센서를 0도(정면)에서 측정**하는 45/0 기하학적 배치를 사용. 이 배치는 난반사광을 최대로 포착하고, 정반사광이 센서로 들어오는 경로를 효과적으로 차단할 수 있음.

### **CRI(Color Rendering Index)란?**

---

CRI는 **연색성(演色性)**을 나타내는 지표로, 광원이 물체의 색을 얼마나 자연광(태양광)에 가깝게 재현하는지를 0부터 100까지의 숫자로 나타냄. CRI가 높을수록 물체의 색을 왜곡 없이 실제와 가깝게 보여줌.

### **고CRI LED를 사용해야 하는 이유**

---

- **정확한 색 측정**: 색상 측정 센서(예: TCS34725)는 물체에 반사된 빛의 스펙트럼을 분석하여 색을 감지하는데 이 때 광원 자체가 특정 색의 파장을 충분히 포함하지 않으면, 센서가 해당 색을 정확하게 인식할 수 없음. **고CRI LED**는 태양광처럼 모든 색상 파장을 고르게 방출하므로, 센서가 물체 본연의 색을 왜곡 없이 읽을 수 있게 해줌.
- **색상 일관성**: 일반적인 저CRI LED는 파란색, 녹색, 빨간색 스펙트럼 중 일부가 부족하거나 과도하게 나타나 색을 다르게 보이게 함. 특히 **빨간색(R9)** 재현력이 낮아, 빨간색 계열의 물체(피부색, 붉은 과일 등)를 정확하게 구분하기 어려움. 고CRI LED는 R9 값을 포함한 모든 색상 지표가 높아, 어떤 색이든 일관되게 정확한 정보를 제공함.

### LED 선택 기준

---

1. **CRI ≥ 95, R9 ≥ 80**
- **CRI(Color Rendering Index)**: 빛으로 색을 얼마나 자연스럽게 보여주는지 지표
    - 100 → 자연광과 거의 동일
    - 80 → 일반 조명 수준
- **R9**: 진한 빨강(red) 색 재현성
    - 일반 CRI에는 빨강 재현이 잘 안 반영됨 → 피부/재질 측정 시 중요
- CRI의 값 뿐 아니라 R9의 값이 중요한가? 에 대한 의문점이 들게 됨
    
    **<LED가 색을 만드는 원리>**
    
    - LED는 빨강(R), 초록(G), 파랑(B) 빛을 섞어서 흰색이나 다양한 색을 만들어 냄.
    - LED가 내는 **빛의 스펙트럼(SPD)**에 따라 특정 색을 얼마나 잘 표현할 수 있는지가 결정됨.
    
    **<CRI와 R9이 중요한 이유>**
    
    1. CRI가 높아도…
        - CRI는 주로 연하고 일반적인 색 평균 점수
            - **R1~R8**: 일반적인 연색(representative color)
            - 주로 파스텔톤 / 밝은 색
        - 빨강·진한 색은 잘 반영 안 됨 → 피부, 빨강 사과, 붉은 옷 등 색이 실제와 다르게 보일 수 있음
    2. R9 같은 지표가 중요한 이유
        - R9 = 빨강 재현성
        - LED의 빨강 파워가 충분해야 **피부 톤, 빨강 물체 색**이 실제 색과 가깝게 보임
        - 측정용 센서로 피부 색, 색 샘플 비교할 때 필수
        
        | 지표 | 색 종류 | 특징/용도 |
        | --- | --- | --- |
        | **R9** | 진한 빨강 | 피부색, 붉은 과일, 빨강 물체 재현성 |
        | **R10** | 진한 노랑 | 금속, 황색 물체 |
        | **R11** | 진한 녹색 | 식물, 녹색 재현 |
        | **R12** | 진한 청록 | 청록 계열 재현 |
        | **R13** | 진한 파랑 | 파란색 재현 |
        | **R14** | 진한 보라 | 보라 계열 재현 |
        | **R15** | 진한 황적색 | 특정 의류, 화장품 재현 |
    
    **<결론>**
    
    - 색 측정용 LED는 단순히 밝거나 흰색이면 안 되고,
    - R9(빨강), R10~R15(진한 색) 재현성까지 충분해야 실제 물체 색을 정확하게 측정 가능
        - 하필 R9 인 이유는 LED에서 **빨강 파장(600~650nm 근처)**을 제대로 내기가 어려움.
        - 화이트 LED는 보통 “청색 LED + 형광체(노랑/녹색)” 구조 → 파랑·초록 쪽은 잘 나오지만 빨강이 약함
        - 그래서 대부분의 LED에서 ‘빨강 부족’ 현상이 생김(R9이 가장 취약하고 중요)
- 피부 색 측정, 컬러 센서 캘리 → R9 포함 CRI 높아야 실제 색 정확
1. **색 온도 5000–5600K**
- **CCT**: LED가 내는 흰색 빛의 색 온도(빛의 느낌)를 수치화한 값
- 5000–5600K → 낮과 비슷한 주광(데이라이트) 흰색
- 이유: 표준 광원 D65(6500K)와 근접 → sRGB 기준, 캘리브레이션 표준화 용이

1. **SPD(Spectral Power Distribution)**
- LED 파장별 출력 그래프
- LED 스펙 시트에 SPD 그래프가 있으면 꼭 확인!
- 왜 중요?
    - CRI만 높다고 실제 색이 정확하게 보장되는 건 아님
    - SPD로 빨강/녹색/파랑 성분이 충분히 나오는지 확인해야 함
        - 빨강(600nm 이상)이 충분한지 → R9 재현 가능 여부
        - 파랑/녹색도 균형 잡혀 있는지 → 전체 색 정확성
