    <aside>
    📌
    
     **Dark 보강 실험 결론 - 핵심 요약**
    
    - **데이터/프로토콜:**
        - 100/110/120 패치 구성 → Dark 패치 +10 / +20 추가
        - 두 가지 학습 전략 비교
            1. **A 방식:** 학습 패치 Dark 패치의 비율 강화 (L/M/D = 0.27 / 0.27 / 0.45)
            2. **B 방식:** 학습 패치 균등 분배 + Dark 추가
    - **A 방식 (Dark 패치의 비율 강화):**
        - 훈련 패치 수 증가(20→60→80) 시 **MAE_avg 안정적 감소**
        - 100 패치일 때 평균 오차율(**MAE_avg)** 가장 낮음 ⇒ 5.67%
        - Dark +10개(110패치)일 때 ±10% 성공률이 가장 개선됨
        - Dark +20개(120패치)는 과적합으로 오히려 성능 악화
        - **적당히(+10) 강화하는 게 최적**
    - **B 방식 , 기존 방식 (훈련 패치 균등 분배):**
        - 훈련 패치 수가 늘어날수록(20→60→80) 오히려 **MAE_avg 증가**
        - Dark 0값(출력=0 수렴) 문제도 개선되지 않음
        - **과도한 Dark 쏠림 → 분포 왜곡으로 성능 저하**
    - **종합 결론:**
        - **Dark 보강은 비율 강화(A 방식)가 효과적**
        - 균등 분배(B 방식)는 전체 성능을 떨어뜨려 적절하지 않음
        - 다음 단계: **A 방식 기준**으로 모델 개선
            - 전체 패치 100→200→300 실험 / 300보다 더 커졌을 때
        - + 센서/광학적 안정화(LED, 노출, 차광) 필요
    </aside>
    
    ## 1. 목적
    
    - 기존 100패치로 학습 시 **Dark(어두움) 구간**에서 신호가 약해짐
    - 특히 **G 채널**이 0에 수렴하거나 매우 낮아지는 경우가 있어 색 오차가 커짐

    ## 결과
    
    ### A. Dark 비율 강화
    
    - **의미**
        - 원래 데이터 분포를 유지하면서 Dark 비중만 살짝 높여 **현실적인 분포 + Dark 보강** 효과를 동시에 얻음
    - **장점**
        - 훈련 패치 수(20→60→80)가 늘어날수록 **MAE가 안정적으로 감소**
        - Dark 패치 개수를 **적당히(+10)** 추가하면 ±10% 성공률도 개선됨
    - **한계**
        - Dark를 **과도하게(+20)** 넣으면 오히려 과적합으로 성능 악화
        - Dark 패치의 0 수렴 현상 자체가 완전히 줄지는 않음 → 평균 오차 개선 효과가 제한적
    
    ---
    
    ### B. 균등 분배 + Dark 추가
    
    - **의미**
        - Light/Med/Dark 버킷을 **무조건 균등 분배**하고  거기에 Dark 패치를 추가(+10, +20)해서 학습
    - **문제점**
        - 데이터 분포가 실제 피부톤 분포와 달라짐 → **Dark 쏠림 현상**
        - 훈련 패치 수(20→60→80)를 늘릴수록 MAE가 **오히려 증가**
    - **한계**
        - Dark를 많이 추가했는데도 **0으로 수렴하는 Dark 패치의 개수가 줄지 않음**
        - Light/Med 영역의 오차가 악화되어 전체 성능이 떨어짐
    - **결론**
        - 단순히 Dark를 많이 넣는 건 도움이 되지 않고 **분포 왜곡**으로 성능 저하

    ### 1. 입력 데이터
    
    - 파일: 데이터 **엑셀/CSV**
    - 컬럼:
        
        `patch_id, Bucket, R, G, B, rs_med, gs_med, bs_med`
        
    - 의미:
        - `(rs_med, gs_med, bs_med)` → 센서 입력값
        - `(R, G, B)` → 정답 (컬러카드 RGB)
        - `Bucket` → Light/Med/Dark × Warm/Neutral/Cool 구간
    
    ---
    
    ### 2. 샘플링 방식
    
    - **A 방식 (Dark 비율 강화)**
        - Light/Med/Dark = `0.27 / 0.27 / 0.45`
        - Dark 비중을 조금 더 크게 해서 훈련 데이터 구성
    - **B 방식 (균등 + Extra Dark)**
        - 9개 버킷을 균등하게 나눈 뒤,
        - Dark 버킷에서만 **+10 또는 +20 패치** 추가
    
    ---
    
    ### 3. 모델 구조
    
    - TensorFlow **Dense Layer (출력 3, bias 포함)**
    - 수식: `y = W·x + b`
        - `W`: 3×3 행렬
        - `b`: bias (3×1)
        - 최종 결과 = **3×4 CCM (보정 계수)**
    - 옵션: `-nonneg 1` → 가중치가 음수가 되지 않도록 제한
    
    ---
    
    ### 4. 학습/검증 (한 번의 rep)
    
    - 데이터 분리: 훈련 세트 vs 검증 세트
    - 학습:
        - 옵티마이저 Adam (lr=0.005)
            - 실 함수를 줄이기 위해 **가중치(W), 바이어스(b)를 조정하는 알고리즘**
            - **learning rate** = 가중치를 얼마나 크게/작게 바꿀지 결정하는 값
        - 손실 함수: MAE (평균 절대 오차)
            - 모델이 얼마나 틀렸는지를 수치로 보여주는 기준
        - EarlyStopping(patience=80) → 과적합 방지
            - 불필요하게 오래 학습하지 않고, **적당한 지점에서 자동으로 중단**
    - 평가 지표:
        - `MAE_R, MAE_G, MAE_B, MAE_avg`
        - **±10% 성공률** (예측 RGB가 정답의 ±10% 안에 들어온 비율)
        - **zero-collapse count** (예측이 0 이하로 떨어진 채널 수 → Dark/G 문제 확인용)
    
    ---
    
    ### 5. 반복 & Best 선택
    
    - 같은 조건으로 **repeats=10** 번 반복 실행
        - 매번 다른 훈련/검증 세트가 샘플링 됨
    - 모든 rep 결과 중 **MAE_avg가 가장 낮은 rep**을 **Best**로 선택
    - Best rep의 CCM 계수(W, b)를 최종 저장
    
    ---
    
    ### 6. 결과 산출물 (엑셀)
    
    - `<out_prefix>_summary.xlsx` 생성
        - **Rep_Summary**: rep별 성능 지표
        - **Train_All**: 훈련에 사용된 패치 목록
        - **Valid_All**: 검증에 사용된 패치 목록
        - **Best_Matrix**: 최적 CCM 계수 (3×4 행렬)
    
    ---
    
    ### 7. 기존 방식과의 비교
    
    ### 1) 뭐가 다른가?
    
    - **기존 방식**: 수학 공식(선형회귀)으로 딱 한 번 계산해서 CCM 계수를 구함
    - **TensorFlow 방식**: 반복해서 조금씩 계수를 바꾸며 최적값을 찾음
        - 오차를 줄이는 방식도 다름 → 기존은 제곱 오차(L2), TF는 절대 오차(L1)
        - 제곱 오차: 예측값과 실제값 차이(오차)를 **제곱**해서 더한 뒤 최소화
        - 절대 오차: 예측값과 실제값 차이의 **절댓값**을 더해서 최소화
        
        | 항목 | 제곱 오차 | 절대 오차 |
        | --- | --- | --- |
        | 오차 민감도 | 큰 오차에 민감 | 큰 오차 덜 민감 |
        | 계산 방식 | 한 번에 공식 계산 | 반복 학습 필요 |
        | 이상치 영향 | 큼 | 적음 |
        | Dark 영역 0 문제 | 쉽게 0으로 수렴 | 상대적으로 안정적 |
    
    ---
    
    ### 2) 어떤 장점/단점이 있나?
    
    장점
    
    - **Dark 영역에서 큰 오차**가 나도 TF는 덜 흔들림 → 안정적
    - 비음수 제약(옵션)을 걸, RGB가 음수로 튀는 현상(0으로 꺼져버리는 값) 완화
    
    단점
    
    - **과적합 위험**
        - Dark 쪽에 지나치게 맞추려다 보면 Light/Med 성능이 나빠질 수 있음
        - 특히 데이터가 적을 때는 더 심함
    - 학습 시간이나 구현 복잡도가 올라감
    - 개선 폭이 제한적일거라 생각
    
    ---
    
    ### 3) 어떤 결과가 나올까?
    
    - **0으로 꺼지는 값(Zero-collapse)** → 비음수 제약을 쓰면 확실히 줄어듦
    - **평균 오차(MAE_avg)** → 기존과 비슷하거나 0으로 꺼지는 값이 줄어들면 조금 낮아질거라 생각
    - **±10% 성공률** → 약간 올라갈 가능성 있음 (Dark 영역에서 큰 오차가 줄면 성공률 ↑)
